# Stage 8：TCR 链聚类与代表序列选择

## 目的

Stage 8 在 IgBLAST 输出之后单独运行，用于在每个输入文件内部处理同一 barcode 下的 TCR 链候选。该阶段不修改原始 IgBLAST 结果，也不进行 TRA/TRB 或 TRD/TRG 配对。

## 输入与基本原则

- 脚本：`08.chain_cluster.py`
- 输入：指定目录下正式的 `TCR.tsv` / `BCR.tsv`（支持 gzip）文件；忽略 `.batches`、postprocess 和状态目录
- 每个文件独立处理，不在 Stage 8 内合并文件
- `sequence_id` 重命名为 `barcode`
- 如果输入已有 `umi_counts`，直接使用；如果没有，则按 Stage 6 的“一行代表一个 UMI”原则将每行计为 1
- 不重新恢复 UMI，不拼接新序列，不生成 consensus 序列

## 处理流程

### 1. AIRR 过滤

保留满足以下条件的记录：

```text
barcode、locus、sequence 不为空
productive = T/TRUE
umi_counts > 0
v_score > 150
v_identity > 85
v_call 或 j_call 至少一个有效
```

当过滤后的数据中 TCR locus（`TR*`）比例超过 90% 时，进一步要求：

```text
v_identity >= 99.7
```

### 2. 建立链身份键

每条记录使用以下字段确定一个独立链候选：

```text
barcode + locus + V gene + J gene + CDR3 nucleotide
```

其中：

- V/J 的 allele 后缀不参与聚类，例如 `TRBV5*01` 和 `TRBV5*02` 按同一个基因聚类
- 使用 nucleotide 形式的 `cdr3`，而不是 `cdr3_aa`
- `d_call`、`c_call` 不作为链身份键，但会保留在输出中
- 缺失 CDR3 时，额外结合序列变体，避免所有缺失 CDR3 的记录被错误合并

### 3. 识别 sequence variant

在同一个链身份簇内部，再按照以下字段识别序列变体：

```text
normalized(sequence_alignment)
```

如果 `sequence_alignment` 缺失，则使用：

```text
normalized(sequence)
```

因此，同一个 `barcode + locus + V + J + CDR3` 下可以存在多个 sequence variant。这些变体可能代表测序错误、比对长度差异或同一链的不同序列表现，不能直接当作不同 TRA/TRB 链。

### 4. 选择 sequence variant 的代表行

如果同一个 sequence variant 有多条输入记录：

1. 将这些记录的 `umi_counts` 相加，得到该变体的总支持数；
2. 从原始记录中选择一条质量最好的记录作为代表行；
3. 不人工拼接或修改序列。

代表行的质量按以下优先级依次比较：

```text
V/D/J/C 比对总覆盖长度越长越好
→ v_score 越高越好
→ v_identity 越高越好
→ sequence_alignment 越长越好
→ 输入顺序靠前者优先（保证结果稳定）
```

最终输出中的序列和 AIRR 注释来自代表行，但 `umi_counts` 使用该 sequence variant 汇总后的总支持数。

### 5. 每个 barcode+locus 最多保留两个独立链

同一个 `barcode + locus` 下，不同的 V/J/CDR3 组合视为不同链候选。候选按以下顺序排序：

```text
链候选的总 umi_counts 越高越优先
→ 比对覆盖更完整者优先
→ v_score 更高者优先
→ v_identity 更高者优先
```

保留规则：

- 第 1 个候选始终保留为主链
- 第 2 个候选满足支持度条件时保留
- 第 3 个及之后的候选不进入主输出
- 因此每个 `barcode + locus` 最多保留两个独立链候选

第二候选的支持度条件为：

```text
top_support / second_support < 3
或
second_support / (top_support + second_support) >= 0.10
```

例如：

| 主候选 : 次候选 | 处理 |
|---|---|
| 42 : 40 | 保留两个，可能是 double TRA/TRB |
| 42 : 10 | 保留两个，次候选占比约 19.2% |
| 42 : 2 | 主输出只保留主候选，次候选进入 summary |

脚本不设置 `MIN_UMI`，因此不会因为 UMI 数量少于某个固定阈值而直接删除候选；但候选仍需有正的 `umi_counts` 支持。

## 主输出中的 `umi_counts`

`umi_counts` 表示被选中 sequence variant 的总 UMI 支持数：

- 只有一个 sequence variant：通常等于整个链候选的 UMI 总数
- 有两个 sequence variant：分别输出两个变体各自的 UMI 总数
- 不是代表行原始记录中的单独 UMI 数

当前 `MAX_SEQUENCE_VARIANTS = 2`，因此一个 `barcode + locus` 最多可能输出：

```text
2 个独立链候选 × 每个候选最多 2 个 sequence variant = 4 行
```

如果后续要求每个 `barcode + locus` 最多输出 2 行，应将：

```python
MAX_SEQUENCE_VARIANTS = 1
```

## 输出文件

每个输入文件生成两个文件：

1. 主结果文件：保留通过 AIRR 过滤和链筛选后的记录
2. `*.stage8_summary.csv`：记录所有链候选、候选排名、支持数、是否保留及未进入主输出的原因

主结果字段顺序为：

```text
barcode
locus
umi_counts
v_call
j_call
cdr3
cdr3_aa
junction_aa
sequence
sequence_aa
productive
d_call
c_call
v_score
v_identity
v_alignment_start
v_alignment_end
d_alignment_start
d_alignment_end
j_alignment_start
j_alignment_end
c_alignment_start
c_alignment_end
sequence_alignment
sequence_alignment_aa
germline_alignment
germline_alignment_aa
```

该阶段的结果仍然是“按 barcode/locus 筛选后的链候选表”，不是细胞层面的 TRA/TRB 或 TRD/TRG 配对结果。
