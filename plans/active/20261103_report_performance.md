# 后续报告生成、计算与查询性能优化方案

日期：2026-11-03。状态：首轮实现、隔离验证、服务器八样本报告重新生成/校验及本地更新均已完成。未推送或部署。末尾完成记录覆盖本文件中的中途状态。

## 目标与约束

缩短首次完整报告、重复生成、仅更新 HTML，以及查询筛选的等待时间。统计含义、科学数值、公开输出内容和离线 HTML 导出能力不变。保留全局最多两个 pipeline、每 pipeline 最多四个 IgBLAST 链任务；第一阶段保留报告与主分析的资源互斥。

## 已核实的现状

- `analysis/repertoire/run.py:94–117,169–220`：统计模块顺序执行，再导出 Excel、PNG、HTML。
- `analysis/repertoire/figure_jobs.py:36–45,89–127`：已有按 CPU/内存约束的最多两个绘图进程；小报告默认串行；基因图组支持缓存。不能把新增多进程描述为从零实现。
- `web/repertoire_analysis.py:273–351`：报告单任务运行，持有平台独占门锁，有进程组取消、RSS 与超时监督。
- `analysis/repertoire/run.py:40–60`：已有统计复用，但会复制私有 SQLite；后续仍生成 CSV、Excel 和图。`web/repertoire_analysis.py:639–661` 已直接返回当前版 HTML，或用旧报告的公共材料动态生成新版 HTML，不重算统计；后者尚未持久缓存，不能误报为完全没有 HTML-only 能力。
- `usage.py:98–115`、`postprocessed_usage.py:118–134`、`scenario_analysis.py:123–135`：按记录反复查询归属；是待测量的优化候选，不能仅凭源码断言耗时占比。
- `primer_metrics.py:153–166` 已在同次执行内复用相同 Raw 来源；`alternatives.py:97–129` 为低匹配样本再次扫描 Raw；`scenario_analysis.py:85–135` 再匹配、读取 Raw/最终 AIRR。
- `AGENT.md` 记录旧版八样本完整报告约 42 分 38 秒、峰值 1014.1 MiB；这是历史观测，不是当前 v31 基准。旧合成绘图测试双进程 12.88 秒对串行 16.26 秒，不能据此承诺完整报告翻倍加速。

## 推荐顺序

1. 建立阶段计时与冷/热缓存基准。
2. 批量关联和写入，减少逐 read 查询。
3. 复用低匹配样本的替代引物匹配证据。
4. 分离统计、绘图、工作簿、HTML 的缓存和生成依赖。
5. 根据基准增加有界样本计算并行和独立图组并行。
6. 优化已完成报告的查询与浏览器筛选；平台级并行另做资源验证。

## P0：测量与批量处理

### 1. 可定位的阶段计时

在 `run.py` 及热点模块边界记录统计、Mapping 匹配、Raw 匹配、替代组比较、存疑组归属、AIRR copy 归属、指标、CSV、Excel、PNG、HTML 的开始/结束、耗时、记录数、读取字节数（可获得时）、缓存命中、worker 数。调度端分别记录排队和实际运行时长；进程树峰值 RSS 与 CPU 采样沿用现有监督，不把父进程 RSS 当总内存。

- 私有工作目录保存轻量 `performance.json`，不加入面向实验人员的报表，不记录原始序列。
- 不逐条写计时日志；按阶段或已有批次更新，避免测量拖慢计算。
- 对关键 SQL 在隔离副本做 `EXPLAIN QUERY PLAN`，对比真实执行耗时。已有复合索引应先复用：`gene_cdr3.py:66` 已覆盖 metric、aa_field，不能只看到 `usage.py:309` 的初始索引就重复添加。

### 2. 逐条查询改为批量关联

修改 `aggregate.py`、`usage.py`、`postprocessed_usage.py`、`primer_metrics.py`、`scenario_analysis.py`：

- 按来源预聚合 ID/canonical 的出现次数与可唯一关联记录，流式 JOIN 代替每条记录重复查询 COUNT/min/归属；不修改只读来源库，在私有统计库或临时表建立必要索引。
- 当前使用 LIMIT 2 判定重复的行为必须等价保留；不能改成任取第一条记录。
- 用有界批次 `executemany`，评估每批 5,000–20,000 条，保持明确事务与进度点；涉及自增 ID 和 calls 外键的表使用批次映射/临时表，不猜测 lastrowid 区间。
- 原始 AIRR 真实比对序列与未剪切 query 不可互换。最终 AIRR 的 identity 和 source/ordinal 对应关系在一次校验后物化，供正常/存疑 copy 分配复用。
- 集合 JOIN 不一定总比索引点查快；只替换经基准获益的热点。包括完整 raw-trace 的特殊分支，但不把其每-read查询量当成默认 Mapping 路径的耗时证据。

## P1：重复工作与缓存

### 3. 存疑组复用匹配结果

修改 `alternatives.py`、`primer_metrics.py`、`scenario_analysis.py`、`catalog.py`：

- 正常样本仍只评估配置引物；维持低于阈值才触发其他组比较。现有替代组比较已使用合并 Matcher，一条序列一次匹配，保留这一做法。
- 对触发比较的样本，在其 Raw/Mapping 比较扫描中保存有界、紧凑的逐记录命中证据；同序列异名仍按现行名称/家族口径处理。
- `scenario_analysis` 消费这份证据和已经验证的 mapping/identity 关联，避免再次读 Raw、再次匹配相同引物、再次解析最终 AIRR。证据包含完整参与记录范围和未命中状态，不能只保存命中导致分母缺失。
- 键包含来源分区、ordinal、阶段、目录版本/引物组身份、读取结构和匹配规则版本；存疑比较阶段与组内语义一致。保存命中事实与阈值决策分离，改变阈值可以重新选组，但不能沿用旧分组决策。
- 不新增完整原始序列副本；必要的私有匹配索引与报告同权限管理，衡量存储增量。恢复/导入旧报告无新证据时回退现有计算。
- 可先做 Matcher 的低风险优化：每条 sequence 只规范化大写一次，保留 IUPAC、read N 不确定、5′全长、同序列别名规则；复杂匹配算法仅在 profiling 显示必要时另做。

### 4. 分层缓存，改界面不重做完整报告

依赖层：来源与归属证据 → 统计 → 公共表 → Excel / PNG / HTML。修改 `run.py`、`io.py`、`figure_jobs.py`、`report_html.py`、`web/repertoire_analysis.py`。

| 操作 | 必须做的工作 | 应复用的工作 |
|---|---|---|
| 修改 HTML 布局/脚本 | 校验公共材料，生成新版 HTML | 统计、私有明细库、CSV、Excel、PNG |
| 修改图配色/展示参数 | 重绘受影响图，更新相关 HTML/清单 | 统计、CSV、Excel和其他图 |
| 修改 Excel 样式 | 重建 Excel | 统计、CSV、PNG、HTML |
| 修改某样本引物配置 | 重算该完整来源作用域的匹配与相关统计，再汇总 | 无依赖变化的样本结果 |
| 修改统计规则/参考来源 | 按依赖使缓存失效 | 仅经过证明不受影响的产物 |

- 第一批先实现展示层复用；样本级统计缓存放在作用域和分片合并明确以后，不一次重构全部流水线。
- 为旧报告的动态 HTML 导出新增私有衍生缓存，以公共材料版本/摘要、viewer、chart schema、rules、palette、固定前端资源版本构成键。同一键的多个访问只生成一次，其他请求等该生成完成或使用既有安全回退；不得在 GET 请求重算统计。
- 每次访问先校验报告归属；缓存不跨用户共享。文件与原报告归档/删除关系明确，使用活跃引用保护和容量上限，不删除正在使用的缓存。
- HTML 缓存位于独立衍生目录，以临时文件原子发布；不就地改原报告 manifest 或私有数据库。完整报告仍使用现有 staging → 校验 → 原子发布契约。
- 重绘只读访问已完成统计库或复用不可变统计材料，避免不必要的全库复制；若任何步骤还需写库，则必须使用独立副本。禁止以硬链接共享一个以后可能被写入的 SQLite。
- 展示选择不能混入科学统计缓存身份；不过快照来源、实际选择集合、完整引物内容与匹配配置、参考版本、06处理来源、科学代码/schema 都必须参与统计缓存判断。现有来源变更检查不削弱。

## P2：有界并发

### 5. 先并发样本计算，不并发写同一个数据库

在消除重复工作后，根据剩余耗时引入 `SCIGBLAST_REPORT_COMPUTE_WORKERS=1|2|auto`。首版默认 1，隔离验证 2 个进程，满足门槛后才调整默认。

- 工作单元为完整的逻辑样本及其来源集合，内部包含共享 Raw/query 的全部链和相关参考组；不能仅按显示样本名、read 数量或链随意切分。
- 只对确实独立的作用域并发，每个 worker 只读来源，写独立私有分片；父进程确定性合并，并正确映射本地记录 ID、usage/source/group 外键，跨分片全局统计由父进程重建。
- 无法证明来源独立或唯一 CDR3 去重边界完整的项保留串行。不能将各分片 distinct 数相加或平均各分片百分比。
- 计算和绘图使用同一份资源预算、分阶段运行，不嵌套变成 2 个计算进程 × 每个 2 个绘图进程；BLAS线程保持 1。
- 使用 spawn 与有界待处理队列；任务只传路径、源标识和小配置，不经进程通信传百万行序列。父进程唯一写完成清单、Excel和最终发布结果。
- 有效并发依据 cgroup/可用 CPU、总可用内存、父进程和worker内存实测估计、磁盘吞吐决定。低内存退回串行或继续排队，不绕过现有进程树 RSS 上限。
- 中断必须取消待执行项、结束本任务子进程、关闭连接并清理未发布分片；不得留下 DONE 或可复用的半成品。自动重试须有次数限制且只在隔离产物上进行。

### 6. 绘图继续最多两个 worker，扩大可复用图种

当前已有两进程按基因图组绘制。优先将昂贵的独立存疑组图/其他图种纳入统一任务清单与缓存，而非直接提升到 4/8 个进程；小报告仍串行。每项独占输出路径，父进程按稳定顺序收集。字体/Matplotlib初始化与缓存指纹按执行复用，不为每张图重复读取固定源码；仍验证有效图文件。

Excel 保持单个 writer：复用样式对象、列宽/格式推断结果；仅在性能数据显示必要且冻结窗格、合并标题、样本分区、筛选、公式防护均等价时评估流式写法。ZIP 已流式、低压缩级别，暂不列为优先改造。

## P2：查询与浏览器

- `web/repertoire_analysis.py:467–519` 的 usage 接口每次重复求汇总，统计完成时物化相同 scope 的汇总；键含 group/primer/segment/metric/aa_field 等实际影响条件，保持返回 payload、单位及筛选语义，按既有请求调用频率决定优先级。
- `records` 已使用 after/id 游标，保留。其 primer JSON 搜索、gene_has 自定义函数若在大库实测慢，可新增带 observation_id 的标准化引物/基因关联表，用 EXISTS 半连接和对应索引筛选，保证多命中不重复返回记录。不要为了展示 50 条每次全库 COUNT。
- `assets/charts.js` 已分表延迟解析；在此基础上按 sample/group/chain/primer/segment 建有界查询索引，复用筛选集合，避免每张图全表反复 filter。

- 继续最多 7 张活动图、顶部 Tab、默认总览全样本；不新增网络/CDN依赖。暂不引入 Web Worker，只有大报告筛选 profiling 仍阻塞主线程时才考虑。

## 正确性与资源验收

1. 在服务器独立目录、固定 CPU/内存限制下，对同一冻结输入分别运行当前版与优化版。先用 H/N1 两样本（正常/低匹配），再完整八样本；不改现有 pipeline 结果或生产数据库。
2. 分别测首次统计、同源重复运行、仅HTML更新、单引物重绘、查询/导出；记录缓存冷热条件，交替运行至少 3 次，比较中位数。另记录排队时间，不拿排队减少冒充计算提速，不强制清服务器缓存。
3. 整数计数、分母、状态、源身份、单位一致；浮点数仅允许预先声明的数值误差。CSV/SQLite逻辑数据、Excel单元格、HTML公共表逐项比较，忽略生成时间/报告hash等非科学字段。PNG核对数据、图数、标签与关键布局；同环境可做像素对比，但不以压缩字节相同作为跨环境唯一标准。
4. 专项覆盖共享 Raw 多链、同名不同来源/参考、重复ID、多重/未匹配引物、read N/简并碱基、不同长度引物、缺 trace/06/C注释、空样本、零分母、存疑组、源文件变化。保留 classified V/J/C 分母、AIRR copy→umi_counts 权重、原序列引物归属、跨链去重与真实比对结果。
5. 单/双计算worker输出等价；取消、OOM预算、超时、worker崩溃、缓存损坏/失效、并发请求同缓存键、用户隔离、归档/删除竞态均验证，失败不发布、不误复用。
6. 浏览器断网验证 PNG/CSV、筛选/分页、图例/缩放、存疑组、最多7图；大列表补50样本/多引物纯交互fixture，测P95与内存，fixture不混入交付真实报告。
7. 建议启用门槛：目标路径至少稳定改善约20%，完整报告无超过约5%的稳定回退，峰值不超过配置预算；双计算worker相较优化串行若提升不足约15%或明显增加I/O等待，保持默认1。门槛是验收目标，不是已测提速承诺；性能噪声大时补测。
8. 验证脚本和产物使用隔离临时目录，按项目约定不新增永久测试目录。部署仍按明确指令执行。

## 不在首轮启用

不取消全局锁，不让多个报告与两个pipeline直接争抢资源，不同时读写主SQLite，不用抽样替代精确计数，不更改匹配/统计规则。若单份报告优化后排队仍是主要等待来源，再单独设计跨pipeline/report/Treemap的资源配额调度；须先验证双pipeline资源基线、来源生命周期保护和公平性。

## 执行批次

第一批：计时 + SQL热点批量化 + 低匹配证据复用 + 旧HTML衍生缓存。

第二批：样本级可恢复统计缓存 + 可选双计算worker + 统一图任务缓存；以第一批基准决定具体热点。

第三批：按使用频率优化接口索引/汇总与大报告浏览器筛选。每批独立验收，保留串行/旧报告回退；不将提速和统计口径变更捆绑发布。

## 执行记录（2026-11-03）

已实现阶段计时、批量写入/来源关联、低匹配组紧凑命中证据、AIRR identity复用、受资源限制的样本归属统计进程、可选样本归属缓存、存疑图组缓存/有界绘图、版本化HTML缓存、查询摘要LRU、浏览器按样本惰性索引/图实例复用/搜索防抖。

针对大表I/O进一步使用覆盖索引只聚合ID/count，避免按ID顺序随机读取大段sequence；AIRR追溯读取沿用CSV引擎，只构造实际使用的列。缓存统计快照在Linux尝试独立inode的CoW reflink，不使用硬链接；不支持时退回普通复制。SQL页缓存按整组内存预算限制在8–64MiB，排序保持磁盘支撑。

默认仍为计算1进程、归属统计缓存0MiB。两个计算worker和缓存是独立可选能力：小任务双进程启动成本较高，未据此上调生产默认。计算并行范围是独立完整样本的aggregate，后续gene/CDR3及copy汇总仍由单一写者统一完成。原跨阶段统计复用保持兼容；未将全套统计改造成可任意拆分的分片系统。

API摘要使用有界版本化LRU（256项），而非首次统计时预先穷举所有查询汇总，以免给以离线HTML为主的场景增加首次生成成本。原查询payload及分页契约保留。HTML缓存新增SQLite读取租约，与归档/删除的事务检查同步；生成首块成功后再发HTTP头，导出/断开均释放租约，归档/删除清理相关缓存。Excel/ZIP现有流式路径本轮保留，未基于猜测重构。
