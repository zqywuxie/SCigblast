# 多链样本报告与基因匹配 CSV 方案

日期：2026-11-03。状态：本轮实现与验证已完成，执行范围及保留项见末尾；未推送部署。

## 1. 需求范围

用户确认：Mapping 后拆分，同一个样本目录下存在多条链的结果，例如 `S01/IGH.tsv`、`S01/IGK.tsv`、`S01/IGL.tsv`。它们属于一个样本，不拆成三个样本，也不按显示名称合并其他任务或批次的同名样本。

目标：报告正确展示共享输入与各链分析；基因匹配支持下载当前筛选的完整 CSV。沿用现有 Mapping、链筛选、06 preprocessing 和科学统计规则。

## 3. 样本与链的展示、计数

### 样本信息

- 同一样本的各链放在一个连续视觉分组内；样本选择器只出现一次样本名称。
- 各链保留自己的类别与引物组信息，不能用最后一条链覆盖整个样本类别。
- 排序采用稳定的样本分组及链顺序 IGH、IGK、IGL、TRA、TRB、TRD、TRG；保留类别排序，在混合类别样本上使用明确的多链标识。
- HTML 与 XLSX 共用一致的样本信息顺序。不同来源/参考上下文保持可区分，不因名称相同而合并。

### 计数边界

| 范围 | 指标 | 规则 |
| --- | --- | --- |
| 样本共享输入 | Raw R1/R2、Clean R1/R2、Merged/Total Reads | 按真实输入来源与 pair 范围计一次，不乘链数 |
| 样本级引物匹配 | Raw/Mapping 输入中的唯一、多重、未匹配 | 保留已有 source/ordinal 去重，不把不同链的匹配总数累加 |
| 样本×链 | Mapping/Retained、逐引物 Mapping rate | 保留对应链范围与既有有效 V/locus 条件 |
| 样本×链×参考上下文 | Total Receptor RNA、Total Unique CDR3s、V/J/C、多样性 | 使用各链 06 与既有可分类分母，不混合不同链的组成 |
| IGH | Isotype、当前 B cell 指标 | 只显示具有相应数据的 IGH 上下文 |

不新增跨链 Unique CDR3 总和或链配对结论。相同数字不是共享来源的证据；缺文件、未处理链和真实零结果必须区分。

### 样本产出比较

- 选择单条链：保留三个柱状指标，Total Reads 明确为该样本对应输入范围的共享 Merged count。
- 多链“全部链”：同一张组合图分为 Total Reads、Total Receptor RNA、Total Unique CDR3s 三个面板，X 轴统一为样本；Total Reads 每样本仅一次，后两个面板按链分组柱状展示。链色一致，悬浮与下载数据明确样本和链。
- XLSX 的用户核查视图将共享输入与链产出分开，避免可直接相加的重复 Total Reads 行；既有底层公共表如需兼容保留，不擅自清空其历史值。
- 优先从已有 stage_volume_summary 的链空值 Merged 行和来源范围获得样本共享输入。不能证明范围一致的旧报告显示不可用，保留可核验的链结果。
- 静态 PNG 与交互图采用相同范围。组合图的活动图数量计入现有最多 7 张限制。

## 4. 报告交互

- 顶部 Tab 与模块独立筛选保持不变，总览默认全部样本。
- 选择样本后链选项只显示该模块有数据的链；只有一条时直接确定，多条时可选全部链或指定链。
- 样本分析、逐引物基因组成在全部链下分链卡片展示；卡片标题包含样本、链、必要的参考上下文，Expression 左、Unique CDR3 右。
- 逐引物组成继续单样本选择，不引入跨样本引物多选；同名引物跨链结果分别保留。
- 样本级引物匹配构成不使用看似生效的链筛选。链级逐引物 Mapping rate 保留链选择。
- Isotype/B cell 仅提供适用上下文，不能让 IGK/IGL 等链出现无意义空面板。
- 基因匹配按样本→链→V/J/C→家族组织；维持每页默认 10 个、可调整和每个上下文独立分页。

## 5. 基因匹配 CSV

在基因匹配工具栏增加“下载当前筛选 CSV”，无需连接服务器，单独发送 HTML 后也可下载。

### 导出范围

- 遵循当前样本单/多选、链、整个样本/单条引物、原组/存疑组、V/J/C、基因搜索和匹配状态。
- 导出所有符合筛选的基因，不仅当前页；翻页或调整每页条数不改变 CSV 行集。
- 界面与导出共用分页前的过滤、上下文去重和家族排序结果。去重键保留来源组、链、范围、引物、情景、基因区和基因，不能仅按 gene 去重。
- 已匹配和未匹配均可导出。缺参考库、未评估、当前隐藏的未唯一归属不改写成未匹配。旧清单沿用可用证据范围，不补造数据库全集。

### 字段与文件

- 基本列：样本、链、基因区、基因家族、基因、匹配状态、结果标识。
- 单条引物/存疑分析时追加引物、引物组、分析类型；不输出整套内部计数字段或私有路径。
- 结果标识沿用 group/reference 上下文的稳定标识，以区分同名样本同链的不同参考结果。
- 文件名采用经过安全处理的任务名、`gene_matching` 和范围标记，保留 `.csv`。
- 复用 CSV 下载基础能力：UTF-8 BOM、CRLF、逗号/双引号/换行转义、文本公式防护、Blob 文件名和及时释放 URL。
- 空结果禁用下载并给出简短状态；不能生成看似成功的无内容文件。

### 8.2 科研查看：优先让图能解释数据覆盖范围

1. **分类覆盖与组成并列，但不改分母。** 当前 V/J/C、Isotype 的可分类分母正确，tooltip 已有分母，06 追溯不可用也有提示；缺的是总 copy 中有多少进入分类。在 Isotype/C 图附近显示紧凑的覆盖数据。例如 N2：`C classified: 259,708 / 750,970 copy (34.58%)`。图内仍以可分类部分归一到 100%。Unique CDR3 覆盖须按自己的去重规则精确取得，不能借用 copy 比例或相加基因内 distinct。仅在可靠证据可得时显示，不恢复底部重复明细表。
2. **建立有方向的查看入口。** 在存疑组/低匹配结果上提供“查看该样本引物分析”；在引物上提供“查看该引物 C 组成/分类覆盖”。点击时显式带入样本、链、原组/存疑组；各模块原有筛选仍独立保留，不暗中同步全局状态。来源不同时展示不可关联，不能凭同名强行连接。
3. **区分扩增识别、Mapping 和 C 分类。** 允许一个紧凑的选中引物诊断区展示 Raw 识别、Mapping 有效 V/locus、06 C 可分类情况。各阶段单位和分母分别保留，不能把 reads 与 copy 串成可直接相减的漏斗。这能帮助定位 N2 的 C 注释缺失，而不仅看到归一化的 IgG 偏高。
4. **统一颜色语义。** 当前总览 Isotype 用主类色，单样本横图在 `assets/charts.js:125` 将 IgM/IgD 设蓝色、其他统一橙色。后续可统一为同主类同色、IgG 亚类同色系；若保留未转换/已转换的双色含义，必须有对应图例，不让同一种颜色在相邻图中无说明地换义。保留克制底色，不增加整页彩色卡片。
5. **比较方式容易发现。** 已有同链基因对齐和参考库校验，不再重复开发；选择至少两个同链可比较样本后，把“同链对齐比较”做成明显操作。对不同参考范围保持区分，不做无法解释的跨链组成合并。

### 8.4 后端：先优化统计与恢复，不盲目增加绘图进程

前四项约占 96.6%。这是单次完整运行，期间容器内存预算有调整，不能与历史耗时比较后宣称提速或变慢。HTML 写入 0.35 秒不等于 CLI 总耗时；轻量 HTML 导出含读取/校验，现有记录约 7.4–7.7 秒。

建议顺序：

1. **将统计检查点纳入正式生成器。** 当前 `run.py:246–253` 在失败后删除全部 staging；上一轮绘图失败导致昂贵统计重做。服务器重试通过外部启动器额外保存了统计检查点，但这还不是正式产品通用恢复能力。统计阶段完整校验后原子保存私有可复用检查点，绘图/HTML 失败只重试展示阶段。身份绑定来源、引物、参考库、06、参数与规则；失效后按依赖重算。检查点不冒充成功报告，正式报告仍原子发布，并有容量/生命周期管理。
2. **细分热点计时。** 在 gene/copy 与 Raw 归属内细分读表、构造 identity、SQL JOIN/聚合/排序、索引建立、写入等；补记录处理量、缓存状态、I/O 与进程树内存。wall 与 coordinator CPU 的差值不能直接认定为磁盘耗时。
3. **先定位重复保存/扫描和未命中缓存原因。** 已有批量 SQL、Raw 命中复用、身份复用、覆盖索引和 CoW 快照，继续针对剩余热点；不再以“新增缓存/多进程”笼统描述。来源匹配后复用成功统计，改 UI 明确走 HTML-only。
4. **并发以完整独立来源组为单位。** 现有可选计算并发只覆盖 aggregate；后续热点若要并发，必须保持共享 Raw 多链在同一工作单元、独立写分片、父进程确定性合并。先比较 1/2 worker 的真实时间和内存/I/O，不默认调高，也不并发写同一 SQLite。
