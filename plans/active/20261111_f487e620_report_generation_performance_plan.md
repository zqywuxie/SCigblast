# 报告生成性能专项方案

2026-11-11。P0 与 P1 首批实现及隔离验证完成，尚未部署。完整 12 样本资源基准、大型明细规范化与分片方案仍待后续验收。

## 目标与基线

保持全部统计口径、逐记录追溯、输出数据与资源锁契约，降低首次报告生成耗时、重复生成耗时与临时磁盘占用。

数据来自 Web 状态库和 `web/runtime/report_work/<报告完整 ID>/performance.json`。阶段有嵌套，不能把子阶段重复相加。写入计数含临时文件、索引、事务等开销，不能直接视为完整数据库复制次数。

实际容器环境与 `web/docker-compose.yml`、`web/.env.example` 的保守默认一致：

- `SCIGBLAST_REPORT_COMPUTE_WORKERS=1`

- `SCIGBLAST_REPORT_MAX_RSS_MB=2048`

## P0 观测与安全基准

1. 将 sample_statistics 拆分计时到按样本读取、引物归属、observations 写入、usage 构建、copy 分配、索引、分片合并、缓存校验及复制。
2. 子进程输出独立的小型性能回执，主进程合并。记录真实 worker 数、串行回退原因、缓存禁用/失效/超限原因、整个进程树峰值 RSS、临时目录峰值占用及磁盘读写。
3. 记录 `MAX_RSS_MB` 向子进程实际 `MEMORY_BUDGET_MB` 的转换。核查父子进程合计约束，不把预算变量误当操作系统硬限制。
4. 固定输入、参考、配置和代码，先选一个 IGH 和一个 MIX 做隔离基准，再以完整 12 样本验收。分别测冷启动、有效缓存重复生成、失败后重试、仅导出 HTML。
5. 同一快照比较 1 和最多 2 个 worker，使用独立输出，保留全局资源门锁、pipeline 2 槽位与每 pipeline 4 链约束。并发不能使峰值 RSS 越过预算或让磁盘吞吐明显恶化。

主要文件 `analysis/repertoire/performance.py`、`compute_jobs.py`、`aggregate.py`、`usage.py`、`web/repertoire_analysis.py`。

## P1 启用合适的并发并减少重复计算

### 有界样本并发

- 复用现有完整逻辑样本分区，MIX 的全部链归同一个 worker，共享来源不重复计数；不按链拆成独立统计任务。
- 参数设计继续使用 `auto/1/2`，按实测内存及 CPU 降级。仅在冷启动 2-worker 基准有收益且预算通过后，更新部署示例和默认值为 auto；保留 1-worker 回退。
- 由大样本优先调度减少末尾等待，最多两个在途任务。只有经验证来源独立的样本才能并行，旧适配器和共享源保持串行兜底。
- 绘图仍有界，统计与绘图按阶段执行，不为节省 40 秒增加整条流程资源竞争。

### 数据读取与 SQLite 写入

- 当前 aggregate 对 item/链循环保存完整 sequence 和重复元信息，usage 再读相关输入。通过细分计时确定热点，建立版本化的可复用标准化记录流或索引，避免同一样本相同来源反复解析。
- 共享序列读取不等于共享链注释。各链比对结果、primer 归属、筛选原因和统计分母保持独立，不能将多链处理简单去重。
- 保留已有 executemany 与批处理，按实测比较批大小和事务边界。检查 EXPLAIN QUERY PLAN，减少相关子查询和重复聚合。
- 只延后统计期间不使用的查询索引，保留必要关联索引与唯一约束。不关闭完整性或原子发布保障。
- 已确认 Raw 预检查结果继续复用，不能为总览重扫 Raw。Mapping 关联仍按必要追溯独立处理。

主要文件 `analysis/repertoire/aggregate.py`、`usage.py`、`batch.py`、`postprocessed_usage.py`、`gene_cdr3.py`、`compute_jobs.py`、`primer_metrics.py`。

## P1 重复生成按变更范围复用

目前已有 HTML 导出、statistics_source、样本 SQLite 缓存和失败后 checkpoint。优先正确使用并补齐失效规则，不重复创建同类功能。

| 变更 | 应执行的工作 |
|---|---|
| 布局、文字、默认筛选 | 校验公共数据后只导出 HTML |
| PNG 配色、标签、尺寸 | 复用统计，只重绘受影响的图 |
| 某个样本引物配置 | 复用其他样本，重算该样本受影响的归属与引物分析，重新汇总 |
| Raw/阶段关联修复 | 定向重建受影响阶段表、Excel 和相关图，不重做 IgBLAST |
| 新样本或输入变化 | 只计算新建/变化样本，其他样本通过指纹校验后复用 |
| 统计规则、参考或 06 发布变化 | 按依赖使相关统计失效，不能只改显示文案 |

### 缓存分层

- 当前缓存保存整份样本 SQLite，代码默认总预算 1 GiB，单项超过总预算一半即跳过。不能认为打开 1 GiB 缓存就能缓存本次大样本。
- 将轻量统计摘要与大型逐记录索引分开管理。公共摘要、表及图使用小缓存；完整明细使用受保护、版本化且可验证的快照。
- 摘要缓存只服务无需逐记录重算的操作。重新归属引物需要有效明细或原始来源，不能拿摘要替代追溯。
- 缓存身份包括 owner、输入/参考版本、完整样本链范围、引物配置与科学实现版本。展示代码变化不误使科学统计失效。
- 大文件哈希及复制不要长时间占用全局缓存锁，改为条目租约/锁与短时元数据发布，防止读取过程中被清理。保留内容完整性验证。
- 保留原子发布、空间预算、LRU 和删除/归档清理。先测磁盘余量及样本大小分布，再决定大型明细缓存额度，不默认复制数十 GB。

主要文件 `private_cache.py`、`compute_jobs.py`、`statistics_checkpoint.py`、`run.py`、`export_html.py`、`figure_jobs.py`、`web/repertoire_analysis.py`。

## P2 大型追溯库存储优化

- 对固定样本/来源/链/primer/gene 元信息使用字典 ID；同一来源的序列通过来源身份＋ordinal 保存一次，多链观察引用该记录。
- 原始序列、实际 mapping 序列与剪切关系分别保留，禁止把内容相同的不同 reads 合并成一条观测。重复 read ID 必须靠来源与 ordinal 区分。
- 优先保持单库消费接口兼容，验证规范化存储能降低写入与空间后，再评估不可变按样本分片、跨样本按需汇总，减少最终巨型库合并。
- 分片化须完整覆盖统计查询、追溯、下载、原子发布、所有权和清理策略，未完成前不启用。
- 不对旧生产库原地迁移。新格式版本化，旧报告可读，失败保留原版本。不得截短序列、抽样统计或丢弃状态记录换取速度。

## 前端进度与用户入口

- 区分排队、样本统计、汇总、绘图、发布。显示完成样本数，当前样本/链与已处理量；将首次运行与复用结果明确区分。
- 估时仅在吞吐趋稳且有足够完成样本后显示区间，缺依据显示正在计算，不给固定虚假 ETA。
- 修改布局后使用“更新报告展示”，引物或数据变化使用“重新分析”；复用策略由服务端验证，不能由浏览器强制跳过校验。
- 失败重试先检查已有统计 checkpoint，展示可复用阶段，保留现有人工 primer 预检查确认流程。

## 验收与发布门槛

- 所有计数、primer 类别/分母、V/J/C、copy、有效 CDR3、Isotype、多样性与 B cell 输出逐项一致，浮点按现有精度规则核对，不变更计数口径。
- 逐记录按来源＋ordinal＋样本链身份验证对应关系；内部自增 ID 可不同，但引用必须等价。覆盖重复/空 ID、同序列多 reads、剪切/未剪切、多重/未匹配、同来源多链。
- 缓存校验覆盖改一份引物、一个样本、一份输入、参考/06 版本变化、损坏快照、权限与并发清理。只展示更新必须证明未重新扫描 FASTQ/AIRR。
- 基准报告同时列冷/热运行耗时、统计阶段时间、峰值总内存、读写量、磁盘峰值、缓存命中及实际 worker。不能仅报 PNG 加速倍数。
- 优先交付 P0＋P1，再决定 P2 是否值得实施。实际收益以同数据基准为准，不预先承诺两倍提速。
- 保留单进程和关闭缓存配置作为回退，未完成 Linux 真实样本验证前不调整在线默认值。用户确认执行方案后实施代码，部署仍依明确部署指令。

## 本轮实施记录

- 新增样本观察、关联索引、基因组成、CDR3、copy 等细分计时；子进程性能回执汇总到主记录。每 2 秒记录本次进程树与工作目录的采样峰值。
- 统计仅读取当前遍历需要的注释列进入 Python，基因 call 解析增加最多 4096 项缓存，完整观测字段与原始材料保留。
- 完整样本任务按结果大小优先，两个任务在途上限不变。子进程预算独立，主进度持续显示正在处理的样本/链。
- 缓存按条目加锁，校验与复制不长期占用目录锁，清理跳过占用条目；新增超限/关闭/命中等记录。单样本结果省去额外库复制，展示重绘复用已校验的 annotation_coverage。
- 默认部署仍为单进程、关闭样本缓存。小数据并发开销明显，不能依据切片试验直接开启生产并发。

验证覆盖合成 H＋MIX 共六链、重复/缺失注释、重复 ID、多重 primer、无效 AA、历史 locus/chain 与 junction-only 输入。优化前后及串行/双进程/缓存复用的全部汇总与 15 张明细表逐项相等。

Linux 隔离验证使用现有资源门锁。合成数据统计为旧版 2.211 秒、新版单进程 1.978 秒、双进程冷启动 2.517 秒、缓存复用 0.837 秒。另从 IgH-1、MIX-1 的六份真实 AIRR 文件各读取最多 3000 行做格式和结果切片验证，旧版单进程 3.095 秒、新版单进程 2.559 秒、双进程冷启动 4.540 秒，全部汇总及 15 张明细表相等。这是有边界的切片测量，不是完整报告提速承诺。

本地另验证了修改一个样本仅使该样本失效、损坏缓存回退重算、占用条目不被清理、超大条目跳过、低内存降级、展示失败后复用 checkpoint、只重导出 HTML 不重做统计。完整报告成功生成 12 张 PNG 与 HTML/Excel，HTML-only 导出约 0.303 秒。五条流程打包检查通过。

剩余工作为完整样本冷/热资源验收，以及根据细分计时决定共享标准化读取、轻量摘要缓存与明细字典化是否值得继续实施。本轮未改生产库格式或在线参数。
