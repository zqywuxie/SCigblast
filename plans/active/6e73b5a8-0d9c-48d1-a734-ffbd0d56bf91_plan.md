# Base AIRR 后处理性能与进度优化

2026-11-10。计算与传输优化、样本并发预算、AIRR 进度和 Treemap 等待状态已在本地实现。完整大样本双任务资源验收待执行，默认保留单样本四个 SHM worker。

## 1. 问题与目标

任务 ZNDX_YL_261110 的 20 个 IgBLAST 链任务已完成，05 执行器仍等待样本后处理。观测时 SHM 使用 4 个 worker，BCR 样本后处理耗时约 39–50 分钟。服务器 CPU 空闲约 89%，容器内存约 21.7 GiB / 300 GiB。以上属于本次快照，后续参数需实测。

目标为缩短 AIRR 后处理耗时、控制并发内存，并展示真实处理状态。验收以现有科学结果、样本身份、行序和正式输出契约一致为前提。全局最多两个 pipeline，每个 pipeline 最多四个 IgBLAST 链任务。

代码依据如下。

- `scigblast/airr_preprocessing.py` 的 `SamplePreprocessing` 固定一个样本 worker，退出时等待所有 warmup。
- `IR_split/pipeline/08.preprocessing.py` 的 `SAMPLES_PER_WINDOW` 内层仍为顺序循环。
- `IR_split/pipeline/models/shm_calculate.py` 每条 BCR 记录分别对 V 区和全长做一次全局比对，完整 DataFrame 在 worker 间传递。
- warmup 只写独立样本检查点，最终 06 统一发布 Datapoint、manifest 和完成回执。

## 2. 实施顺序

### P0 建立性能基线与真实进度

1. 在隔离输出目录复用已完成的 05 输入，选择 IGH、IGK/IGL、TCR、混合多链样本。记录读取、过滤、各指标计算、SHM、junction 输出和最终汇总耗时，以及进程树 CPU、容器内存峰值、吞吐量。
2. 新增本次 attempt 独立的后处理观测存储。复用进度模块的读取、限量查询和容错方式；独立存储避免现有 `Progress` 初始化清空 IgBLAST 进度表。
3. 每样本记录排队、读取、指标计算、SHM、写入、检查点复用、完成、失败重试。SHM 由父进程汇总完成批次的记录数，限频写入，避免逐 read 写库。独立心跳反映长批次仍在运行，检查点就绪与最终 DONE 分别展示。
4. Web 同时显示 IgBLAST 已完成和 AIRR 正在处理。展示样本完成数、运行样本、排队数、SHM 已处理量及该样本耗时。稳定吞吐建立后展示当前 SHM 剩余时间区间。
5. 保留执行阶段的回执规则，05 等待期间通过活动子阶段呈现 AIRR 处理。进度完成与正式阶段完成分开判定，最后汇总完成后再显示任务完成。

### P1 降低 SHM 数据传递和重复计算

1. 给 SHM 调用增加显式 worker 参数，兼容现有调用者；Base/IR 调用传入各自预算，移除 adapter 对 `mp.cpu_count` 的临时覆盖。
2. worker 只接收行序号及 SHM 必需字段，返回行序号和十个 SHM 结果。原始表留在父进程，按原行序组合结果，保持后续权重与聚合顺序。
3. 将按 worker 数切出的少量大块改为有界小批次。限制在途批次数量，按实际工作量调节批量，缩小长尾并支持进度更新。
4. 对完全相同的序列与参考序列组合复用计算，缓存同时限制条数和字节，核算全部 worker 的累计占用，并在样本结束释放。保持输入原样与既有异常行为，失败计算不入缓存。记录命中率和内存，低命中时关闭。重复记录仍按原始行和权重参与统计。
5. 首版使用现有比对打分与首个 alignment 选择逻辑。任何减少 alignment 枚举的改动须单独验证同分比对下的 mismatch、insertion、deletion 和比例完全一致后再采用。

### P2 开启受预算约束的样本并发

1. 增加 Base 后处理样本并发参数，作用于 `SamplePreprocessing` 的独立样本子进程。样本全部所选链成功发布后才进入队列。
2. 统一约束样本并发和 SHM worker 总量，父进程、过滤和读取阶段的开销纳入资源预留。`TOTAL_PROCESS_BUDGET` 明确实际约束范围，禁止每个样本重复领取整份总预算。
3. 基准按 1 样本 × 4 workers、1 × 8、2 × 8 依次比较。2 × 8 是候选配置，需同时满足 CPU、内存和双 pipeline 验收。每 pipeline 后处理合计 64 GiB 可作为该配置的初始验证预留，最终以峰值和余量确定。两个 pipeline 各用 2 × 8 时合计最多 32 个 SHM worker，另计父进程、读取与 IgBLAST 资源。
4. 重叠阶段按 IgBLAST 加后处理的总资源进入现有共享门锁；最终独立 06 同样按后处理预算申请。现有后处理内部 `MEMORY_BUDGET_GB` 主要用于配置记录，`memory_ok()` 检查主机余量，需要补充真实准入约束。使用容器 cgroup 限额与当前用量，并结合主机余量，预算不足时降低并发或等待。
5. 所有样本子进程及 SHM worker 保持现有运行槽位、预算 FD 和进程组生命周期。停止、异常、重试时取消未启动任务并收束在运行子进程。
6. 每个样本只有一个写入者，独立检查点和 junction 输出原子发布。warmup 全部退出后由最终 06 单点汇总。warmup 失败交由最终阶段受控重试并显示失败原因。
7. 首版沿用当前指纹失效规则，代码升级可能使历史后处理检查点重新计算。验证和上线预估中计入这部分成本。

## 4. 验证与上线条件

- 科学一致性。旧版与新版逐记录对比全部 SHM 字段，再对比 Datapoint、junction 数据与 manifest 的科学字段、行数、顺序、权重和缺失值。身份、路径、时戳等运行元数据按语义核验。
- 边界数据。覆盖空表、单条记录、重复序列、indel、同分 alignment、短片段、缺失 C 注释及多链混合样本。使用独立合成夹具和真实数据切片。
- 共享模型回归。通过 Base 正常入口验证完整样本，同时验证 IR 既有调用兼容性。
- 资源与故障。验证两个 pipeline 同时运行、容器内存紧张、worker 异常、停止、恢复、缓存复用与失效。确认全局运行槽位、链任务上限、后处理预算均有效。
- UI。验证 mapping 全完成但 AIRR 未完成、部分样本失败、空样本、复用、旧任务缺少新进度、窄屏和深色主题。观测写入失败应允许计算继续。
- 性能。报告端到端耗时、SHM 耗时、吞吐和内存峰值，选择实测更快且双任务内存稳定的配置。加速倍数由实测给出。
- 工程检查。Python/Bash/JS 检查、运行时和 bundle 检查。验证脚本及夹具放系统临时目录，完成后清理。
- 上线。隔离验证通过后，在活跃任务结束的部署窗口启用。先验证单样本 8 workers，再启用通过双任务验收的样本并发参数。运行中的旧任务继续使用已有代码与参数；新增配置支持回退至单样本 4 workers。
