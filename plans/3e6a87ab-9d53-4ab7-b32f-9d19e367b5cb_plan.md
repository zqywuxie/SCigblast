# Treemap 后置分析输出接入方案

日期：2026-10-21。状态：已实施，待部署。包含“创建任务可选＋独立生成入口”。

## 目标与已确认范围

- 用户已选择 `E:/Desktop/treemap_code/treemap_g.py`：单链 QR 风格图＋多链合并图。
- 覆盖现有五条注册流程的成功任务；新增派生图片、统计及 Web 入口，保持原分析阶段顺序、筛选、参数、TSV 内容、文件命名、缓存和 DONE 契约。
- 提供两个入口：创建分析任务时可勾选“分析完成后生成 Treemap”；独立 Treemap 页面选择已有任务结果或服务器结果目录，扫描后选择样本和链生成。不需要 Submission，不重新运行 IgBLAST。
- 新建任务的选项建议默认不勾选，用户明确选择后主分析成功才排队生成；未勾选和历史任务均不自动补算，后续可从独立入口或任务详情生成。绘图失败可独立重试。
- 本方案不接入原项目 Flask/API/Worker 栈、Tetris、TopClone 交互及 V/J 环形图。

## 已核实的现状

- 源脚本的 `load_chain_clones()` 分块读取 CSV/TSV（含 gzip），过滤 `productive == "T"` 和非空 CDR3；按完整 V/J/CDR3 的记录数聚合，不读取输入 copy 权重。
- CDR3 优先使用 `junction_aa`，不存在时才使用 `cdr3_aa`，不逐行混合两个字段；V/J 等位基因和多重命中字符串保留原值。
- `generate_qr_treemap()` 生成 V→J→CDR3 的 3000×3000、300 DPI PNG，颜色由克隆标识稳定决定。
- `save_combined_treemap()` 使用固定链区版式与黑色间隔；缺链不占位，现有链重新铺满。链区面积不代表链间丰度。
- `treemap_code/tmp/run_zndx_treemap.py` 已有从 Pig `chain_summary.csv` 的真实 `output_path` 读入并调用上述函数的适配示例。
- Web 尚无通用后置绘图入口：`web/app.py:watch_job()` 根据 runner 返回值和现有完成标记更新状态，`stage_reports()` 主要面向表格，`artifacts()` 不识别 PNG。
- 五条 runner 通过根目录 `pipeline_resource_lock.sh` 共享资源锁。归档由独立进程执行，`web/archive_results.py` 当前会把 PNG 打包后删除在线副本。

## 1. 绘图模块与计数契约

新增独立的 `analysis/treemap/` 包，提供来源适配、聚合、绘图与 CLI。将源脚本必要函数移入项目，去掉硬编码目录、年龄项目命名及基于旧 PNG 是否存在的缓存判断；记录来源与绘图版本，运行时不再依赖桌面目录。

首版保留源脚本的记录数口径：

1. 每条合格最终记录计 1，跨分块合并相同的完整 V/J/CDR3；禁止把 copy、umi_count、umi_counts 自动改为面积权重。
2. 不修改原文件或重新执行主流程筛选。图的额外 productive/CDR3 选择只用于派生结果，统计中说明。
3. 页面、统计和 manifest 标注“最终结果记录数”；不称为 UMI 数、细胞数或 reads 数，不暗示不同流程的计数可以直接比较。
4. 空 V/J 沿用脚本原行为；缺必需列、无有效记录、源文件缺失分别记录，不能自动补 productive=T、补假链或补克隆。
5. 保留颜色、层级、布局、翻转、尺寸和固定合图比例。原 `_squarify_items()` 的头部列表删除可改成游标遍历，但必须验证布局坐标和图像一致。

若后续需要 UMI/copy 加权，须作为明确的新计数模式设计，不能改变本版图形解释。

## 2. 按流程确定唯一输入

来源适配器处理有权限的关联任务输出，或独立入口扫描并确认的服务器结果目录，产出统一的 `(sample_key, sample_label, chain, source_path, column_mapping, file_version)` 清单。关联任务按下表识别其最终来源：

| 流程 | 读取位置与规则 |
| --- | --- |
| IgBLAST base / Pig IgBLAST | 使用 `05.igblastn_out/<dataset>/chain_summary.csv` 中成功、可识别链的单链真实 `output_path`。校验其位于本任务输出内；支持旧嵌套布局与新 sample-v1 布局。排除 TCR/BCR、数据集聚合文件，避免重复计数。 |
| reMapping | 通过 `web/mapping_results.py` 的清单及最终可用性规则读取 `03.umi_count` 文件，尊重原任务样本/链选择。保留 sample_key 区分不同子目录同名样本，不重新匹配原始 CSV。 |
| IR split | 使用 `08.preprocessing/<dataset>/processing_manifest.csv` 对照 `junction_peps` 中的最终逐样本逐链文件；不读取 Datapoint 指标表作为序列数据。根据实际任务变体和 preprocessing 选项判断是否存在最终结果；无该步骤的任务明确标为本版不适用，不静默退回前一阶段。 |
| 10X split | 根据当前阶段输入/结果清单映射到 `08.cluster` 最终文件，保留相对样本身份，以 locus 拆分链。排除 `*.stage8_summary.csv` 等统计表，不重复读取单链与聚合文件。 |

每个来源只扫描一次，分块拆链并统计。不得仅凭目录 basename、文件 stem 或不可靠的 V 基因前缀合并样本或猜链。同一 sample_key/chain 对应多个源文件时，按明确清单合并非重复分片，身份冲突则报错。

独立目录模式只接受已完成注释的 CSV/TSV（含 gzip）：必须有 productive、v_call、j_call 及 junction_aa/cdr3_aa。优先识别以上流程的结果清单；没有清单时按明确的 sample_CHAIN/sample__CHAIN 文件命名及 locus 识别候选样本链，显示相对路径供确认，无法可靠识别的条目要求显式指定身份或标为不支持，不能从 V 基因猜链。原始 FASTQ/FASTA、尚未注释的官方 CSV 不适用，页面提示先运行对应分析。

目录扫描生成用户、路径、文件版本绑定且有有效期的快照；分页/搜索仅影响显示，跨页选择按稳定条目 ID 保存。提交时用服务端快照核验所选集合，执行前再次确认版本。默认全选有效样本，只开放实际识别到的链；允许用户调整样本和链，不让缺列文件在生成时才无提示失败。

## 3. 后台运行与资源调度

- 新增 `web/postanalysis.py`，用一个 SQLite `derived_runs` 表和一个后台 dispatcher 管理，沿用当前单 Web 实例部署，不引入额外队列服务。
- 记录 owner_id、source_type、可空 parent_job_id/attempt_no、run_id、选择快照、模块/版本、metric、状态、进度、进程身份、起止时间、错误及结果 manifest。关联任务按 task/attempt/版本/选择/输入版本去重，独立任务按用户绑定的来源与选择签名去重；不伪造一条 pipeline 任务来运行绘图。
- `CreateJob` 新增 `generate_treemap: bool = False`，保存到 options_json，并在详情配置中可见；不作为主分析参数传给 runner。`watch_job()` 仅对用户启用且成功的任务轻量入队，保持主任务 SUCCEEDED、时长与邮件语义；来源扫描、聚合、渲染均不得进入请求线程或 `PROCESS_LOCK`。
- 独立入口使用同一个绘图队列和执行器，支持任务命名、选择、排队、取消、独立重试及历史查看，不另建计算服务。使用现有任务作为来源时绑定该任务的 attempt 和生命周期；纯目录模式绑定输入文件快照，不依赖 parent_job。
- 运行状态独立为 queued/running/succeeded/partial/empty/failed/interrupted/cancelled。主任务失败、主动停止或仅等待审核不启动绘图；绘图错误不改变主任务状态，不额外发邮件。
- 一个后台调度器，每批由一个轻量监督进程启动有界单链 worker（默认最多 2 个，可设为 1 恢复串行），实际并行数受 CPU 配额和可用内存限制；合图仍逐样本执行。整组继承与 pipeline 相同的 `SCIGBLAST_RESOURCE_LOCK_FILE` 锁 FD，每批结束释放。主分析排队后不启动下一批；取消、超预算及监督进程异常时停止并核验整个进程组。worker 仅传路径及少量 JSON，不跨进程复制大表/图片；单链失败独立记录并可重试。
- 分块读取、只加载所需列、定期合并聚合表，逐链释放对象，不缓存全量原始记录或所有图片。依据真实大样本测量再确定分块及时间/内存预算；唯一克隆数仍可能导致内存增长，超预算明确失败，不用截断 TopN 或丢弃低频克隆换取成功。必要时再增加磁盘聚合。
- 子进程通过现有进程身份机制记录与核验，支持超时/用户取消；不能凭旧 PID 杀进程。重启恢复排队项，未确认结束的运行项标为中断，核验旧进程退出后方可重试。
- 启动协调只补齐明确启用的新任务成功事件中漏入队的记录，并恢复独立入口已提交的排队记录，不补跑所有历史任务；绘图队列错误不得阻止主分析调度。

## 4. 输出组织、缓存与发布

关联任务输出放在：

```text
<task_output>/analysis/treemap/attempt-<n>/run-<id>/
  manifest.json
  treemap_summary.csv
  individual_treemaps/<safe_sample_key>/
    <sample>_<CHAIN>.png
  multi_chain_treemaps/<safe_sample_key>/
    <sample>_ALL_CHAINS.png
```

各样本链统计统一汇入 treemap_summary.csv，避免再输出重复的逐样本统计文件。

纯目录模式独立生成的结果由服务器分配到 `<default_output_root>/<user>/treemap/<北京时间目录>/run-<id>/`，内部采用相同 manifest/统计/图片结构。用户只选择输入，不指定输出目录；不能把派生图写回输入目录。关联已有任务时始终写入该任务的派生目录，避免来源任务续跑、删除或归档时遗漏生命周期约束。

- 安全目录标识必须防止同名样本、清洗后名称和路径分隔符碰撞；展示保留原 sample_key，不能生成重复嵌套的样本目录。
- manifest 固化来源类型、owner、真实来源、文件版本、选中样本链、列映射、筛选条件、metric=records、绘图版本、可选关联任务 attempt，以及每个产物状态、相对路径和文件版本。
- 统计包含 sample_key、chain、有效记录数、克隆数、状态与原因；“文件缺失”不能展示成零克隆。
- 先生成临时 PNG，校验图片有效性/尺寸后原子发布；统计和 manifest 同样原子更新。接口只展示 manifest 已确认的产物，不从散落的旧 PNG 推断本次成功。
- 输入处理前后核对文件版本；发布前再次核验输入版本和 run_id，关联任务还核验 task attempt/状态。改变输入或重试后，不展示旧图为当前结果。
- 空链显示“无有效记录”，缺链不造图。部分链失败时保留其他成功图；允许生成仅包含成功链的合图，但图旁明确“部分链”，列出遗漏原因。
- 同一运行的失败重试复用已完成且输入/版本一致的单链图；强制重生成创建新 run，不覆盖正在下载的旧文件。

## 5. Web 展示与接口

### 创建分析任务

在新建任务正文末尾增加简洁的“后置分析”区，提供一个默认关闭的勾选项：

```text
□ 分析完成后生成 Treemap
  根据本任务最终样本与链结果，生成单链图和多链合并图。
```

不复制一套样本链选择器；自动模式沿用主任务实际选择，跳过没有有效结果的链并说明原因。这里的“完成后”指原有 mapping 及该流程已有结果整理步骤全部成功，不插入 IgBLAST 与整理之间。配置检查、提交流程、失败后恢复和重新 Match 均保留该选项；检查结果和详情配置展示是否启用，旧任务缺字段按关闭处理。

### 独立生成页面

从首页提供“Treemap 生成”入口，进入独立 `/treemap` 页面，不混入第六条 IgBLAST pipeline。操作顺序：

1. 选择来源：“已有分析任务”或“服务器结果目录”。任务列表只展示有权限、已完成且未归档的任务；目录支持已有受控目录浏览与路径输入。
2. 点击“扫描数据”，展示识别到的样本、链、来源文件及不适用原因；默认全部有效样本，可搜索/分页/批量选择，只选择需要的链。
3. 展示确认摘要：所选样本数、样本链文件数、记录数计数说明、将生成单链图与合并图。扫描阶段不承诺精确总行数，不为了显示计数同步全量读取大文件。
4. 点击“生成 Treemap”，后台排队；显示进度、错误和取消/重试入口。
5. 页面提供“我的 Treemap”历史和结果查看；用户仅查看自己的运行，管理员按现有权限管理。

关联已有任务与手填路径指向平台任务输出时，必须按数据库任务归属识别并绑定来源；不能借目录入口绕开其他用户任务权限。纯数据目录沿用管理员配置的可访问输入根，不放宽到整个服务器。

### 图片展示

在任务详情的“输出文件”中增加“Treemap 克隆分布”区域，保持原表格入口和 Tab 数量：

- 展示等待、生成中、完成、部分完成、无有效记录或失败，以及已处理样本/链数。
- 结果默认不加载图片，显式选择样本和链/多链合图后点击查看，仅加载单张预览。支持放大、PNG/统计 CSV 下载，以及全部结果/当前样本 ZIP；历史图片在 ZIP 中也规范为两个图片目录，原文件不移动。
- 图旁固定说明：“块大小表示当前链内相同 V/J/CDR3 的最终记录数；合并图链区面积只用于排版。”
- 历史成功任务提供“生成 Treemap”，失败项提供“重试绘图”，操作忙碌时禁止重复提交。没有符合输入契约时说明原因。
- 主任务完成但图仍排队时显示“分析已完成，Treemap 正在排队生成”；已有完成邮件继续链接任务详情，不承诺图在邮件发出时已就绪。

独立页面与任务详情复用同一结果组件；关联运行在两个入口查看到同一套状态与产物，独立目录运行在自身结果页展示。

建议接口：

- `POST /api/treemap/scan`、`GET /api/treemap/scans/{scan_id}`：来源识别及绑定用户的分页扫描结果。
- `POST /api/treemap/runs`、`GET /api/treemap/runs`、`GET /api/treemap/runs/{run_id}`：按快照和选择创建、列出和查看独立/关联运行。
- `POST /api/treemap/runs/{run_id}/retry`、`POST /api/treemap/runs/{run_id}/cancel`：重试与取消。
- `GET /api/treemap/runs/{run_id}/files/{artifact_id}`：预览/下载服务端产物。
- `GET /api/treemap/runs/{run_id}/download?sample_key=...`：流式 ZIP，未指定样本时下载全部图片和统计 CSV，指定时仅下载该样本图片。
- `GET/POST /api/jobs/{id}/treemap`：任务详情的关联运行查询与生成入口，内部复用以上服务，不重复实现调度。

访问沿用当前用户/管理员权限及写操作来源校验；独立记录显式检查 owner_id，关联来源额外检查任务访问权。下载只接收服务端产物 ID，不接收任意路径；重新核验 owner、可选关联任务、attempt/run、manifest、后缀、真实路径范围及符号链接。PNG 预览使用明确 image/png，表格继续复用有界预览机制，不把图片送进 stage-summary 表格解析。

## 6. 续跑、删除与归档

- 对重试、重新 Match、删除及输入重建入口统一协调派生任务：取消待运行项，确认已核验的运行子进程停止后再更改/删除来源。发布仍须执行 attempt/run 守卫，避免竞态。
- `web/archive_results.py` 是独立进程，不能只靠内存锁防止归档冲突。归档认领 ARCHIVING 的 SQLite 条件增加“不存在活跃派生运行”；派生入队/认领反向检查任务未归档及 attempt 有效，使用短事务原子协调。
- 延续原归档保留策略：图片随完整结果归档，在线副本可移除；页面显示“图片已归档，请下载完整结果”，不误报生成失败。
- ARCHIVING/ARCHIVED 不允许补生成，不自动解压归档；归档期间已有派生任务必须先完成或取消并确认停止。
- 纯目录生成没有关联 pipeline 任务，保留独立的取消/删除规则，不受原 pipeline 14 天归档脚本自动处理；首版不额外改变这类新产物的清理策略，文档明确其范围。

## 8. 实施顺序与验收

1. 先移植独立 QR 核心，针对源脚本固定输入核对聚合数据、布局坐标、颜色、尺寸与合图比例，再接五条流程来源适配；先用已有 ZNDX/Pig 示例验证源文件发现。
2. 接入后台运行、输入快照与原子发布，然后接新建任务可选开关、独立页面及共用图片区域和安全下载；最后补齐重启/续跑/删除/归档协调、Docker 与文档。
3. 新增聚合测试：跨 chunk 同克隆、非 T productive、空 CDR3、列优先级、原输入 copy/UMI 值不影响面积权重、空表/缺列/同名样本不混合。
4. 绘图测试：1/多链、仅 TCR/仅 BCR、缺 TRD/TRG、七链合图；无伪造填充、稳定配色、3000×3000 PNG。相同 Pillow 环境下对比源脚本像素/布局；不跨版本依赖 PNG 文件字节哈希。
5. 后台/API 测试：仅勾选后成功触发、未勾选及旧任务不触发、失败/审核/停止不触发；独立目录/关联任务的扫描快照、跨页选择、过期或跨用户快照、同目录不同选择、重复请求、部分失败重试、源版本/attempt 改变、主任务优先和锁释放、子进程退出、重启、越权/路径越界以及归档双向竞争。
6. 复跑已有通知、任务生命周期、mapping_results、表格预览/下载及归档相关测试，确认主任务状态、邮件触发、运行时长与原有 TSV/DONE 不受影响。
7. 用 Playwright 验证桌面/移动端的新任务开关及失败恢复，独立入口两种来源、扫描/搜索/跨页选择、生成/取消/重试、样本链切换、图片放大下载、空/失败/部分/归档状态及轮询不夺焦点；测试不发真实邮件。
8. Linux/Docker 验证图形依赖和打包完整性。使用只读真实输入、独立临时输出分别抽样五流程及大克隆样本，记录聚合耗时、绘图耗时、峰值 RSS、产物数量；比对原分析文件校验和。真实服务器测试按用户指定连接与目录执行，不修改在线结果、生产并发或配置。

完成标准：创建分析任务时可选结束后生成；独立入口可从有权限的任务或服务器目录扫描、选择数据并生成可追溯的单链/多链 PNG；无数据与绘图失败可区分；原分析流程及输出内容保持不变。
