实施结果：`outputs/72c4d9a1/report.html`（HTML v30）；20份汇总表的计数/分母/百分比与原报告逐项一致，仅计数单位修正。验证见同目录 `data_validation.json`、`browser_validation.json`、`edge_validation.json`。原始pipeline数据及服务器报告未修改。

## 审阅范围与结论

基于 `outputs/2b0d74ec/report.html`（v29）、相关源代码、现有截图和验证记录。现有验证记录无浏览器错误；本轮未重新运行浏览器测试（file URL 被工具限制），未修改或重新计算报告。

报告已有样本信息、数据变化、产出、Isotype、基因组成、引物与基因匹配等模块。主要改进方向是图表独立可读、计数单位准确以及跨样本可比较性，不是继续增加指标或重复数据表。

## 第一期：可靠解读与导出

### 1. PNG 保留必要的分析身份（P1，确认存在的问题）

现状：`report.js` 的 figureNode 将图表和静态文件名交给 `charts.js` exportPNG；只导出 canvas，不包含外层样本/引物标题。基因图内部只有 `C/V/J gene usage`，导出后难以区分样本、引物、原组/存疑组，以及 Expression 与 Unique CDR3。改变筛选后仍可能下载为 all_samples 文件名。

实施：
- 共用结构化图表上下文：样本或样本集合、链、引物、基因区、阶段、指标、原组/存疑组、分页。
- PNG 使用一行英文主题和一行简洁范围标识；不重复长篇统计说明。指标必须进入图片，存疑分析保留 Suspected 标记。
- 根据当前筛选生成文件名；多样本集合使用数量加短哈希，避免过长名称及错误 all_samples 标识。
- 导出保留当前图例选择和缩放；不能因为隐藏图例或只展示部分基因而重算分母。
- 页面不新增重复标题区；静态 PNG 与交互导出采用相同命名/指标规则。

关键文件：`analysis/repertoire/assets/report.js`、`analysis/repertoire/assets/charts.js`、`analysis/repertoire/chart_data.py`；静态绘图需要同步时修改 `render_usage.py`。

### 2. 计数单位与范围校正（P1，确认存在的问题）

现状：`isotype.py` 共用 unit=reads，但后处理 abundance 使用 SUM(weight)，unique_cdr3 使用 distinct AA count。实际 CSV 的 postprocessed 行也带 reads 单位。现有页面统计口径已经说明 copy/umi_counts，不应重复添加整段说明。

实施：
- abundance 按来源明确为 reads 或 copy（AIRR umi_counts）；Unique CDR3 的计数单位为 distinct CDR3 count。
- tooltip 的 Count/Denominator 使用对应单位，保持 count、denominator、percent 数值不变。
- 对基因/Isotype 补足分母含义：当前区段可分类数据；Unique CDR3 按当前统计类别去重，不能将各基因计数之和解释为全样本唯一 CDR3。
- Total Reads 继续使用 Merged。明确其属于所选输入范围；共享输入的多链可能重复出现该值，不能跨链相加。保留现有按 input pair 取数逻辑。
- Total Receptor RNA 保留名称，定义为 AIRR umi_counts 的 copy 总和，不等同于已验证的独立 UMI 分子数。

关键文件：`analysis/repertoire/isotype.py`、`analysis/repertoire/report_rules.py`、`analysis/repertoire/assets/charts.js`、`analysis/repertoire/output_metrics.py`；检查 `workbook.py` 与 CSV 消费方的兼容性。

### 3. 样本产出支持按指标查看（P2，呈现优化）

现状：三项指标同轴，较小的 Total Unique CDR3s 柱容易被 reads 数量压缩。

实施：保留用户指定的默认“每个样本三根柱”；增加简洁切换：全部指标 / Total Reads / Total Receptor RNA / Total Unique CDR3s。单指标模式复用当前图框并调整轴域，所选样本之间保持同一轴域。避免双 Y 轴、默认对数和无依据的跨单位归一化。N/A 与真正 0 分开处理。

关键文件：`analysis/repertoire/assets/report.js`、`analysis/repertoire/assets/charts.js`、`analysis/repertoire/report_html.py`。

## 第二期：针对性比较与复核

### 4. 可选同链基因对齐比较（P2）

保留当前默认逐样本排序，以及 Expression / Unique CDR3 左右布局且共享基因顺序。新增比较模式时：
- 仅比较相同链、基因区、指标且参考集合可核实兼容的样本；来源无法核实时提示，不静默合并。
- 使用所选样本已观察基因的并集，统一顺序与百分比轴域；不把数据库全部零匹配基因塞回组成图。
- 同一基因在所有比较图中处于相同位置；分页对齐，沿用最多 7 图的限制。
- 区分“参考包含但本次无匹配”与“参考不包含/数据不可用”，后者不能填零。
- 不因图例隐藏、分页或筛选显示基因而重新归一化百分比。
- 各样本仍独立统计，不合并生物样本，不自动给出优劣排名或显著性检验。

关键文件：`analysis/repertoire/assets/charts.js`、`analysis/repertoire/assets/report.js`、`analysis/repertoire/chart_data.py`。若公开数据不足以确认参考兼容性，只增加必要的参考标识，不暴露服务器路径。

### 5. 离线当前图数据导出（P2，可后续实施）

在现有 PNG 导出旁提供轻量的“导出数据”菜单，利用 HTML 已内嵌汇总数据输出 CSV，供科研人员核算。包含当前样本/链/引物/分析组、指标、分子、分母、单位、百分比。与当前图筛选及排序一致；保留原统计分母，注明被隐藏系列，不将显示范围误作全部统计范围。保护以 =、+、-、@ 开头的文本字段，避免电子表格公式注入。无需联网，不增加底部统计明细。

关键文件：`analysis/repertoire/assets/report.js`、`analysis/repertoire/assets/charts.js`、`analysis/repertoire/chart_data.py`。

## 保持不变与审阅边界

- 顶部页签、中文操作界面、英文图题；模块筛选独立，总览默认全部样本，逐引物组成单样本。
- 基因匹配家族分组、默认每页 10 条且可调整；不恢复底部大表格、unique junction 或候选基因分析。
- 存疑引物组已有“基于现有 mapping、未重新去引物/比对”提示及未归属 copy 数，无需重复添加；原组与存疑组不能当成独立生物重复。
- 现有分类分母未发现确认错误。本轮没有重新验证全部原始 reads，因此不作为所有统计均正确的完整审计结论。
- 多样性计算保持原流程；需要说明记录丰度与按 CDR3 合并丰度的统计层级，不能未经确认修改为另一种克隆定义。未确认同源样本/重复设计前，不提供生物学差异结论。
- 不修改 01–06 pipeline、原始数据、引物归属、数据库或当前分析数值。

## 实施后的验收

1. 用现有 8 样本报告回归，另验证共享输入的多链情形、零分母、真实零值、缺失数据和参考不一致情形。
2. 对比修改前后的 count/denominator/percent：第一期应完全一致，变化仅限单位、展示和文件名。
3. 分别导出 H、N1 原组、N1 存疑组、两个样本子集的 PNG；脱离 HTML 后能够识别样本范围、链、引物、指标和存疑状态。
4. 在断网浏览器打开单个 HTML，验证 PNG/CSV 导出、图例、分页、手机与深色模式；页面无外部资源依赖及 console 错误。
5. 比较模式中同一基因位置与尺度一致；隐藏系列不改变百分比；非适用数据不出现伪零值。
6. 验证样本产出默认仍为三柱；切换单指标后小数值指标可读，原值不变，跨链不重复汇总共享 Total Reads。
7. 不增加常驻图表数量、不加载逐 read 数据；检查 HTML 大小和切换耗时相对当前基线未明显恶化。

建议先实施第一期，再根据实际比对需求实施第二期。所有验证在用户授权实施后进行。
