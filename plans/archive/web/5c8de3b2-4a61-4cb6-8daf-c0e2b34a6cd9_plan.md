## 范围与约束

- 面向实验与数据分析人员，默认操作清楚，页面文字精简，技术细节按需展开，沿用克制的现有配色。

- 不改变 pipeline 的科学分析阶段、筛选、计数、参数、最终 TSV 内容、命名、列和记录顺序；派生图与 Clone Top 保留现有计数契约。
- 原方案保留主流程单任务运行；后续用户明确要求“最多跑 2 个”，现已改为全用户共用 2 个运行名额及对应文件锁槽位，第三条起排队。用户归属、attempt 隔离、进程身份核验、停止/续跑/删除/归档语义保留。

- 设计阶段仅维护方案；收到用户“执行修改”后实施功能并进行隔离验证，不修改在线部署。

## 第一批：操作连续性与前端状态

### R1 扫描使用候选状态，成功后整体替换

目标文件：`web/static/directory-input.js`、`web/static/index.js`、`web/static/treemap.js`，必要时在 `web/static/ui.js` 增加小型状态辅助。

- 分离当前已确认的扫描/草稿、正在读取的候选结果和来源上下文；扫描开始只更新 busy 状态，不直接清空已选样本和编辑值。
- 上下文包含流程、来源模式、输入路径/来源任务及对应 revision/attempt。新请求使用单调 generation；每个 await 返回后先核对 generation 和上下文。
- 分页结果先放入临时集合，全部成功才提交到界面。相同来源按稳定条目 ID 与来源版本核对已有编辑；版本变化的条目不得直接沿用旧确认状态。保留首次扫描和重新 Match 各自的默认选择规则。
- 输入来源变化或重新扫描未成功时，旧草稿可以保留供恢复，但不能作为当前来源提交。按钮 readiness 由当前扫描状态决定，不能只看旧 scan_id 或已选数量。
- 初始文件扫描仍为未知进度，显示活动状态和耗时；POST 返回 total 后，分页阶段显示“已读取 X / Y 项”。不把读取清单的进度当作文件系统扫描百分比。
- 同来源失败展示简短错误和重试入口，保留编辑。只对可重试的分页 GET 做有限退避；不自动重发扫描 POST，401/403/快照过期转为对应恢复操作。
- 搜索/翻页继续仅影响显示；提交请求仍来自完整状态快照，不从当前页 DOM 收集。重新 Match 的锁定路径、流程和来源保持原规则。

验收：修改名称和链后让第 2 页失败，编辑不丢失；A 来源慢响应晚于 B 到达时不能覆盖 B；同页/跨页选择一致；显式空选择仍被拒绝；旧快照过期、源文件变化不能绕过后端检查。

### R2 稳定 DOM、焦点与 Treemap 最新请求

目标文件：`web/static/index.js`、`web/static/job.js`、`web/static/treemap.js`。

- 任务列表按 job.id 更新已有行，只替换变化单元格；状态时间、进度局部更新。操作者选项仅在集合变化时更新，避免每次刷新重建。
- 对确需替换的区域保存稳定 focus key，覆盖任务链接、详情链接、操作按钮和 details summary；节点移出当前筛选时回到合理邻近项或列表刷新按钮，不强行跳页。
- `region()` 使用已有 details ID 或明确 key 恢复展开和 summary 焦点，不能仅按可变化的文案寻找身份。当前代码保留展开状态的行为继续保留。
- Treemap 历史列表 signature 仅包含实际显示字段（ID、名称、状态、日期、选择）；进度变化不重建没有显示进度的历史按钮。
- 将 `selectRun()` 的递归 150 ms 定时器替换为“一个在途请求＋一个最新待处理 ID”。在途响应结束后只读取最新目标，旧结果不能覆盖当前详情；重复选择同一项不重复清空已显示的预览。
- 复用任务列表已有 busy/pending/latest-query 思路，不引入新的轮询协议。必要时扩展 `Submission.api` 接收 AbortSignal，但客户端取消不等同于服务器工作已取消。

验收：聚焦任务链接/summary/历史按钮时经历多次轮询仍可操作；延迟响应下 A→B→C 最终只显示 C；在途请求与待处理任务数有界；图片仍须用户显式查看，切换任务/attempt 清除旧结果。

### R3 保持页面简洁，补足关键状态

目标文件：`web/static/index.js`、`web/static/style.css`、`web/static/treemap-view.js`、对应模板。

- 手机端保留本次执行次数，可紧凑排版或合并到运行时长元信息；不依赖隐藏最后一张摘要卡来适配窄屏。
- 配置检查使用返回的阶段语义，例如“匹配检查通过”或“分析检查通过”；不要把尚未检查的后续分析环境暗示为已全部通过。
- `analysis_check_pending` 当前是 `preflight.py:109-112` 的正常非阻断提示，继续按需展开。真正需要处理的错误显示简短摘要、定位字段，保留原阻断规则；不因有 warning 就全部展开。
- Barcode 目录的“不能选为 CSV”与“可以打开浏览”分开表达。当前后端 `app.py:339-342` 只返回 selectable=True 的文件；不能声称存在已确认的不可选文件提交漏洞，也不能禁用所有 selectable=False 目录。修正目录导航的 aria-disabled 语义即可。
- Clone Top、统计 CSV 与 ZIP 在同一区域采用一致的紧凑下载入口；文件不存在时保持明确的可用性状态，不误写为“没有克隆”。本批不增加默认表格预览或改变下载范围。

验收：390px 下时长/阶段/执行次数可获得；正常提示不铺满页面；Barcode 目录仍可键盘打开、最终只能选择符合类型的文件；CSV/ZIP 下载链接和权限不变。

## 第二批：重复解析、锁与数据库查询

### R4 为目录扫描快照增加有界只读缓存

目标文件：`web/input_manifest.py`、`web/tests/test_directory_input.py`。

- 缓存键包含规范化 state root、token 及快照文件版本（设备/inode、大小、mtime_ns、ctime_ns）；命中前确认文件存在且版本未变，读取前后核对版本。
- 采用小型 LRU，限制快照数、总 rows 和估算字节，超预算对象不缓存；预算由阶段 0 的 RSS 数据确定。单实例、单 worker 下先使用进程内缓存，不增加外部缓存依赖。
- 每次读取仍验证 owner、pipeline、规范化输入路径及 expires；缓存命中不是授权。清理、删除、替换及过期都必须使旧对象不可用。
- 缓存对象只读，分页返回轻量拷贝，创建 manifest 不得原地修改缓存。正式提交继续重新核验输入文件、选择与版本。

验收：同一快照多页访问只需一次解析；删除/替换后不能命中旧对象；跨用户、跨目录、跨流程及过期 token 被拒绝；高频扫描不造成缓存无限增长。

### R5 reMapping 索引按 key 合并构建

目标文件：`web/mapping_results.py`、`web/tests/test_mapping_results.py`。

- 全局锁仅保护 LRU 和在途构建表；同一完整 key 共用一次构建，不同任务分别构建，CSV 读取与解析移到全局锁外。
- key 继续包含输出根、dataset、attempt、options、execution 和三份摘要版本；发布前重新核验签名。持续变化时沿用当前最多两次尝试与 pending 降级，不能发布已知过期的文件描述。
- 构建异常必须释放在途项并通知等待者，避免死锁；保留现有 32 任务/100,000 权重预算和页面范围的实时文件可用性核验。
- 链/状态索引或搜索结果缓存仅在过滤耗时经测量后添加；不改变缺失文件、未知清单和生物学零结果的区分。

验收：受控阻塞 A 任务的 CSV 解析时，B 任务查询可完成；同 key 并发只构建一次；构建期间替换摘要、改变 attempt 或删除文件时不会返回可下载的旧描述。

### R7 按实际查询增加少量索引

目标文件：`web/app.py` 的 schema/list_jobs、`web/tests/test_job_filters.py`、`web/tests/test_execution_preview.py`。

- 使用代表性数据和 `EXPLAIN QUERY PLAN` 验证普通用户 owner＋创建时间、owner/status 和管理员常用筛选。优先评估 `(owner_id, created_at, id)` 等少量组合，避免枚举所有字段组合建立索引。
- 同一创建时间提供稳定的次排序；仍返回当前账号可见范围的精确统计、操作者列表和当前筛选的精确 total。
- 先保留 OFFSET 和页码交互。只有深页实测成为主要瓶颈时，再单独设计游标分页；`%关键词%` 搜索不能宣称会被普通 B-tree 自动加速。
- 不增加跨用户统计缓存；若引入短期缓存，必须以相同权限范围和数据版本隔离，并在任务状态变化时失效。

验收：新增/改名/同秒任务、操作者筛选、分页和普通用户隔离保持一致；比较冷/热查询和浅/深页，不只比较一条 SQL 的速度。

## 第三批：Treemap 存储单独改造

### R6 新运行采用增量子表，旧运行继续兼容

目标文件：`web/postanalysis.py`；建议新增 `web/derived_store.py`；`web/app.py` 的删除事务；`web/tests/test_treemap.py`；Docker 白名单与 `web/check_bundle.py`。

这项涉及恢复与兼容，不与第一批 UI 修改捆绑。先测量 1,000/10,000 项下累计状态写入、全清单 stat 次数和 SQLite 锁等待，确认收益后执行。

| 存储 | 建议内容 |
| --- | --- |
| `derived_runs` | 沿用 owner、parent/attempt、dedupe、status、PID/token、时间、done/total；新增 `storage_version`，v2 的 data_json 仅保留小量元信息 |
| `derived_items` | `(run_id,item_id)`、稳定 ordinal、sample_key/chain、status/error、计数、artifact_id、单项 sources 与 clone_table 小 JSON |
| `derived_artifacts` | `(run_id,artifact_id)`、稳定 ordinal、kind、sample/chain、label、相对路径及文件版本 |
| `derived_samples` | `(run_id,sample_key)`、稳定顺序与合图完成状态，替代不断增长的 composed_samples 数组 |

- 调度只取有界 queued 项，批次完成只更新本批 items/artifacts、相关 sample 和进度；以状态条件保证重复恢复不会重复计数。不能每批重新拼装完整旧 JSON 或双写完整 JSON，否则仍保留原瓶颈。
- 来源验证调整为：运行开始/发现时验证清单，启动与发布每批时验证该批来源，合图验证依赖图片，最终发布前完整验证一次。依然要在实际使用/发布之前发现对应源变更，不能只依赖陈旧缓存；取消/attempt 校验每个发布事务仍实时进行。
- 详情和最终 manifest 由存储适配器按原顺序恢复现有形状，按需全量构建一次；列表仍只读摘要。source/path/内部 clone_table 元数据继续不回传。CSV 合并继续由独立子进程完成。
- 无 storage_version 的记录视为 v1，沿用旧读取和调度；新 run 使用 v2。已完成旧 run 不自动迁移、不补算；旧 run 的重试先继续 v1。可选迁移只能对无活动进程且已确认 group gone 的记录，在单事务核对完整子项与顺序后切换版本。
- 保留 run/item/artifact ID、dedupe_key、PNG/clone_table_version、attempt、路径和公开状态语义。文件先原子发布再登记；崩溃产生的未登记文件不能通过 API 下载。
- 删除任务须同步清理子表，不能假定 SQLite 外键已开启；归档仍基于 derived_runs 在事务内认领。所有 worker 退出并确认前不能清 PID，未知进程身份继续保留。
- 降级边界必须写清：旧程序不能直接读取仅含小元信息的 v2 data_json。优先向前修复；必须降级时停止相关工作并执行受控兼容导出后再切换旧版本，不能只回退代码。

验收：v1/v2 新建、partial、取消、重启、重试、缺失 Clone Top 中间表、删除/归档交错和迁移中断均覆盖；v2 的累计持久化工作随条目/产物规模近似线性，主任务优先和最终图/表内容保持一致。

### R8 归档暂以量测为主

目标文件：`web/archive_results.py`、`web/tests/test_archive_results.py`。

分开量测目录枚举、压缩、源文件对照校验和删除阶段。若大文件树的路径清单内存确为问题，再改为确定性分批枚举/流式清单；保留原有归属、真实路径、符号链接、文件变化和完整性核验，不以跳过校验换取速度。压缩包内部文件内容与保留策略必须一致，不能用 gzip 文件字节是否相同代替内容验证。
