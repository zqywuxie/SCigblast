# SCigblast Pipeline 与 Web 优化计划及执行记录

日期：2026-09-25

## 范围与目标

检查注册到 Web 的 IR、10X、Base、Pig、reMapping 流程，以及 Web 的任务列表、任务详情和 Match 页面。重点检查可复现的数据正确性问题、断点续跑、资源使用和用户交互。优化后通过回归测试和容器/Linux 环境检查验证。

## 计划与实施

### 1. 修复 10X reducer 重跑后保留过期结果

发现 reducer 会把新汇总行追加到旧状态；源数据或参数发生变化、UMI/barcode 消失时，旧行可能继续出现在结果里。已调整为按样本完整重建并替换状态，清理重复汇总逻辑，并在 checkpoint 中记录 phase1 TSV 文件数和 SHA-256。未提交 phase2 时必须确认 payload 完整；只有 reducer 结果已提交且指纹匹配时才允许清理 TSV。覆盖成功重建、空结果、payload 丢失和已提交后的清理场景。

验证：10X Linux 测试 5 项通过。

### 2. 校验 Base/Pig 阶段产物后再复用 DONE 标记

发现仅检查 DONE 标记或任意一个输出文件，会让缺失、空文件或不完整的阶段结果被误判为成功。已基于阶段摘要清单逐样本检查预期产物；缺失产物会使对应阶段重新运行。FASTQ 必须非空，允许合法空 FASTA，并校验 PANDAseq 的 summary 与配对记录。

验证：Base 4 项、Pig 2 项相关测试通过；另有阶段标记回归测试通过。

### 3. 限制并发内存压力

将容器可用内存检测扩展到 cgroup v1/v2，并新增基于 `flock` 的共享资源锁。IR、10X、Base、Pig 和 mapping CLI 在运行资源密集的单样本任务前获取结果盘上的同一把锁；Web 单任务队列之外的终端任务也因此串行化。多数据集父进程在分发子任务前不持锁，避免父子等待造成死锁。锁文件路径可通过 `SCIGBLAST_RESOURCE_LOCK_FILE` 配置，默认放在共享结果卷。

同时为 IR 代表序列处理限制未完成的 futures 数量。10X stage8 读取 AIRR 输出时只加载过滤、聚类和结果输出所需列，跳过其他 IgBLAST 注释列；单文件输入直接返回 DataFrame，避免一次 concat 复制，并在过滤和聚类后尽早释放大表引用。IR FASTA 读取使用上下文管理文件句柄并支持 gzip。

验证：Docker cgroup v2 下四类 runner 均能读取内存限制；模拟 cgroup v1 回退路径得到预期值。两个独立 Linux 进程的锁竞争测试通过。31 个 shell 文件通过 `bash -n`。

### 4. 提高 Web 任务列表与 Match 交互的准确性

任务过滤和分页统一在服务端完成，避免只过滤当前页造成总数、空状态和分页不一致；前端搜索增加防抖和过期响应保护。Match 扫描按请求复用结果，并根据摘要元信息检查是否需要刷新。失败任务展示直接查看日志的入口，列表和任务详情显示最近更新时间。

验证：Web Linux 回归 70 passed、3 skipped。Playwright 检查登录、任务过滤、Match 搜索及更新时间显示通过；无页面脚本错误或失败请求，浏览器对缺少 favicon 的默认 404 提示除外。

### 5. 保持旧版 reMapping 输出兼容

当新格式 `.tsv` 不存在时，Web 将历史 `.filtered.tsv` 作为最终结果展示；`.raw.tsv` 继续隐藏。添加针对旧输出的回归测试。

验证：包含兼容性改动的 Web 回归已通过。

### 6. 降低 mapping FASTA 转换内存

`mapping/fasta.py` 使用标准库 CSV 流式读取，避免一次加载完整表格。合成压力测试处理 500,000 行、125.8 MiB CSV，在 1 GiB 容器限制内生成 129.0 MiB FASTA；转换器 peak RSS 12.6 MiB，耗时 2.31 秒。该结果只代表合成输入下的转换压力测试。

### 8. 使用服务器 mapping CSV 完成 Linux 端到端基准

使用 `/colddata/SCigblast/data/SCigblastWeb/web_test/20260909/raw/artificial_peps/AL_S004_v7__TRB.csv`，通过当前工作区版本依次运行 CSV→FASTA、IgBLAST、UMI count 整理；结果写入容器 `/tmp` 隔离目录，没有改动 Web 服务、部署配置或正式结果目录。输入 177,480 条序列，最终 UMI 文件 172,938 行数据；三个阶段及总流程 DONE 标记均生成，退出码为 0。转换器输出与容器基线逐字节相同（68,513,642 bytes，SHA-256 `67248a30…9dea4a9df62ff`）。

当前转换器耗时 1.30 秒、peak RSS 12,292 KiB；容器基线耗时 4.21 秒、peak RSS 245,172 KiB，输出完全一致。端到端流程墙钟 19:11，CPU 使用率 202%，`/usr/bin/time -v` 的 peak RSS 414,836 KiB，无 swap；IgBLAST TSV 约 531 MB，UMI count 输出约 531 MB。该 CSV 适合验证大量序列的 Linux 正确性和资源行为；fixture README 说明配套 FASTQ 是每对仅 20,000 reads 的功能测试子集，不能作为生物学规模吞吐基准。

## 其他验证

### 9. 服务器 10X FASTQ fixture 全流程

在容器内使用当前工作区版本运行 fixture 的两个 10X 样本（每个 R1/R2 各 20,000 read pairs），结果仅写入 `/tmp/scigblast-10x-bench-20260926`。测试 workbook 的 Note 指向其旧 fixture 根路径，因此只在容器 `/tmp` 复制并改写测试用 workbook；原始 fixture 和正式数据未修改。Match、fastp、TSO/引物预筛、clean header、PANDAseq、split/representative、IgBLAST、stage8 均成功，9 个 stage DONE 标记齐全，退出码 0。阶段 6 输出 7,151 条代表序列；stage8 两个 AIRR 文件共 1,907 行，过滤后 795 行，最终输出 772 行。端到端耗时 96 秒，CPU 使用率 170%，peak RSS 1,349,484 KiB（约 1.29 GiB），无 swap。该小型 fixture 证明 Linux 功能链路可运行，但不作为生产吞吐基准。

### 10. 服务器 Pig FASTQ fixture 全流程与运行环境问题

同一 fixture 的两个 Pig 样本也完成了当前工作区版本的 fastp、clean、PANDAseq 和 3 个 IgBLAST chain task，最终生成 7,977 和 3,087 行 TCR TSV，所有 stage DONE 标记齐全。第一次运行发现 PANDAseq manifest 读取硬编码调用 `python3`，而容器只保证配置的 `${PYTHON_BIN}` 可用；已改为使用 `${PYTHON_BIN:-python3}`。继续验证又发现 IgBLAST 汇总列 `output_path` 未写入，导致 runner 即使获得全部成功的 chain TSV 仍拒绝标记完成；已将已校验 task TSV 路径写入 summary，并复跑确认 runner 正常完成。重试复用了 IgBLAST task 完成标记，没有重复做序列比对。首次完整计算用时约 23 秒，峰值 RSS 199,768 KiB，无 swap。测试 workbook 仅在 `/tmp` 改写 Note 根路径，原 fixture 未改。

### 7. 使用工作区真实 10X 大表验证 stage8

在工作区的 `10X_split/data/all_samples_TCR.tsv`（651,240,105 bytes、204,460 行、111 列）上运行 stage8：保留 87,637 行 AIRR 记录，最终输出 25,558 行。最终版只读取必要列、跳过单文件 concat，并在阶段间释放大表引用；10 ms 采样的最近一次耗时 40.439 秒、peak RSS 1,037.7 MiB。`HEAD` 版读取全部列，在相同数据上的基线为 43.986 秒、1,660.7 MiB。最终版耗时约少 8.1%、采样 peak RSS 约少 37.5%；输出 SHA-256 与基线相同，均为 `7d9ba946…16618da`。前两次仅应用列裁剪时结果分别为 40.234 秒/980.2 MiB 和 40.067 秒/984.9 MiB。以上为 Windows 工作站上的真实 10X 数据结果，仍需在生产 Linux 环境复测。

另在 80 MB、27,180 行的 `TCR.tsv` 上，旧版与当前版输出 SHA-256 同为 `76173190…f09a3d`。发现同目录已有 `TCR.stage8_summary.csv` 记录的 input_rows 为 115,281，而现存 `TCR.tsv` 为 27,180 行、`all_samples_TCR.tsv` 为 204,460 行；`TCR_filter.tsv` 也不是当前 stage8 输出。它们不是同一次运行的可信对照，故正确性比较使用同一输入分别运行 HEAD 版和当前版，而没有把这些旧文件当作预期结果。

- mapping 测试 10 项通过；IR 测试 9 项通过（ResourceWarning 作为错误处理）；10X pipeline 测试 6 项通过；共享锁测试通过。
- JavaScript 语法检查、Docker Compose 配置检查、Docker 镜像构建、容器 `check_runtime.py` 和 `git diff --check` 均通过。
- Docker Desktop 已停止，恢复到本轮检查前的状态；未部署或推送。

### 11. 服务器 IR raw/presplit FASTQ fixture 全流程

在当前工作区版本下分别运行 IR raw 两样本和 presplit 单样本。raw 模式完成 8/8 阶段、14/14 IgBLAST task、preprocessing 保留 2 个样本，墙钟 78 秒、peak RSS 207,976 KiB、退出码 0；presplit 模式对 12,457 条 reads 完成既有 UMI header 导入，产出 9,343 条代表序列，7/7 IgBLAST task 和 preprocessing 成功，8/8 阶段 DONE，墙钟 99 秒、peak RSS 248,440 KiB、退出码 0。测试暴露 `04.clean_header.sh` 与 `07.work_igblastn.sh` 裸调用 `python` 的容器兼容问题，现统一使用配置的 Python 路径；10X IgBLAST helper 也已统一。presplit 重跑还暴露旧目录残留会被递归扫描，生成重复样本和空 representative FASTA 并中断 IgBLAST。现仅对真正的旧 Lane/pair 命名补层，并在 clean、PANDAseq 全阶段重跑时重建派生目录，在 representative 全阶段重跑时重建 FASTA 索引。最终 presplit 回归只发现一个 10_LF 样本且全流程通过。

## 12. 浏览器实测 stop/resume

使用当前工作区 Web 源码启动独立临时容器，并仅以临时 CSV 与长驻测试 runner 验证详情页交互；未连接或修改现有正式服务。浏览器创建 reMapping 测试任务后，停止操作将状态置为 STOPPED 并终止 runner；断点续跑重新启动 runner、状态进入 RUNNING；重复停止/恢复一轮仍符合预期。测试结束确认数据库状态 STOPPED、pid/pgid 为空并删除测试容器和临时目录，原 scigblast-web 容器仍为 running。此项关闭前述 Web stop/resume 浏览器验证缺口。

生产规模 FASTQ 吞吐、峰值 RSS、I/O/磁盘与 Linux stage8 生产性能对照仍未测量：给定目录中的 FASTQ 仅有每对 20,000 reads 的测试子集。现有结果只支持功能与小样本资源行为结论。
