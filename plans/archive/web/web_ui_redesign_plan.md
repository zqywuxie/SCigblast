# SCigblast Web 界面规范化改造计划

## 目标与边界

将当前 Web 页面改成克制、规范、便于长期监控的科研运维控制台。保留 FastAPI、Jinja2、原生 JavaScript、CSS 和 Docker 部署方式，不引入 React/Vue 或新的前端构建体系。

本次只修改任务创建、任务监控、Match 审核、日志阅读和操作反馈；不修改四条 pipeline 的科学计算逻辑，也不新增样本管理、结果分析、文件上传、工作流编辑或完整账号系统。

## 当前主要问题

1. 首页 Hero、轨道装饰和大标题占据首屏，任务列表反而被压缩。
2. 新建任务表单长期占据左侧空间，路径较长时难以填写和核对。
3. Match preview 已有结构化 API，但详情页仍以 JSON 展示，无法快速审核 ERROR。
4. 状态只显示名称和百分比，没有清晰说明用户下一步应确认、续跑还是检查错误。
5. 日志每两秒重新读取并渲染尾部内容，文件增大后效率下降，用户滚动时也容易被刷新干扰。
6. 任务参数、操作记录和 Match 信息都以原始 JSON 呈现，不符合日常操作界面习惯。
7. 内联 JavaScript 集中在模板中，页面维护和错误处理较困难。

## 推荐页面结构

### 首页：任务控制台

- 顶部只保留产品名、服务器状态、运行任务数和“新建任务”主按钮。
- 任务列表占据完整页面宽度。
- 支持按状态、Pipeline、操作者筛选，并支持 Job ID/Dataset 搜索。
- 每行显示状态、Dataset、Pipeline、当前阶段、阶段进度、操作者、开始时间、持续时间和错误摘要。
- 行尾只显示当前可执行动作：
  - 待审核：查看 Match
  - 运行中：查看详情、停止
  - 失败或停止：查看详情、续跑
  - 已完成：查看详情、查看输出路径
- 移除 Hero、轨道图、背景网格、渐变光晕和宣传性指标。

### 新建任务：右侧抽屉

- 点击“新建任务”后打开右侧抽屉，不长期占用任务列表空间。
- 操作顺序固定为：选择 Pipeline → 填写路径 → 专用参数 → 确认摘要。
- Pipeline 使用四张紧凑选择卡。
- IR 才显示 `input_mode`、`variant`、preprocessing。
- IR/10X 才显示 Barcode CSV。
- Dataset label 根据输入目录实时给出默认值预览。
- 路径输入提供即时状态：未验证、可用、不可用。
- 保留最近使用的操作者和路径到浏览器 localStorage，减少重复输入。
- 主按钮统一命名为“创建任务并执行 Match”，明确第一次不会直接启动完整流程。
- 暂不开发服务器文件浏览器，继续使用绝对路径输入，保持权限边界简单。

### 详情页：固定任务栏 + 标签页

顶部固定显示：返回、Dataset、Job ID、状态、当前阶段、进度以及当前主操作按钮。

正文使用五个标签页：

1. 运行概览：输入、submission、barcode、output、操作者、时间、尝试次数、错误摘要和阶段时间线。
2. Match 审核：结构化表格、OK/ERROR 统计、只看 ERROR、错误原因和确认按钮。
3. 实时日志：增量加载、暂停刷新、自动滚动、ERROR/WARN 过滤、复制最近日志。
4. 输出文件：展示重要产物路径、是否存在和文件大小，不经 Web 下载大型文件。
5. 参数与操作记录：使用键值表和时间线，不显示原始 JSON。

详情页按状态突出最重要内容：待审核优先提示 Match，失败优先显示错误，运行中优先显示阶段和日志。

## 视觉与交互规范

- 使用标准后台布局，背景 `#F6F7F9`、白色面板、深灰正文。
- 主色统一为深蓝绿色；成功、警告、失败分别使用绿色、琥珀色、红色。
- 使用 8px 间距体系、6–8px 圆角、轻边框和少量阴影。
- 中文作为主要界面语言；Pipeline、Match、Dataset 等必要术语保留英文。
- 日志和路径使用等宽字体，其余内容使用系统无衬线字体。
- 按钮全部使用明确文字，不再用 `■`、`↗` 作为唯一含义。
- 补齐 hover、focus-visible、disabled、loading、错误提示和 `aria-live`。
- 移动端任务表切换为卡片布局，操作按钮保持至少 40px 点击区域。

## 必要后端调整

这些改动只服务于界面展示，不改变 runner 或 pipeline 行为。

1. `pipeline_registry.json` 增加 description、stage_labels、form_fields，用注册表驱动表单和阶段中文名称。
2. `GET /api/jobs` 增加 `status`、`pipeline`、`operator`、`query`、`limit`、`offset`，支持服务端筛选和分页。
3. `GET /api/jobs/{id}/match-preview` 增加 total、ok、error、unmatched 统计。
4. 新增轻量路径验证接口，只检查路径存在性、类型、权限和允许根目录，不扫描 FASTQ 数量。
5. 日志接口改成按字节 offset 增量读取，返回 `content`、`next_offset` 和 `reset`。
6. 状态轮询仍为两秒，但 Match、日志和 artifacts 只在相应标签页激活时请求，避免重复读取和整体 DOM 重绘。

## 涉及文件

- `web/templates/index.html`：全宽任务控制台和新建任务抽屉。
- `web/templates/job.html`：固定任务栏和五个标签页。
- `web/static/style.css`：重建规范化后台视觉系统。
- `web/static/index.js`：首页表单、筛选、分页和操作反馈。
- `web/static/job.js`：详情标签、Match、日志和任务操作。
- `web/app.py`：分页过滤、路径验证、Match 统计和增量日志。
- `web/pipeline_registry.json`：补充展示与动态表单元数据。
- `web/README.md`：更新页面使用说明。

## 实施顺序

1. 先实现任务列表服务端筛选、分页、路径验证、Match 统计和增量日志接口。
2. 重构首页为全宽任务控制台和右侧新建抽屉。
3. 由 Pipeline 注册表动态生成专用参数字段。
4. 重构详情页为五个标签页和固定操作栏。
5. 将 Match JSON 改成可筛选表格，将操作记录改成时间线。
6. 完成日志暂停、自动滚动、增量加载和错误过滤。
7. 统一视觉、文案、键盘焦点、加载和错误状态。
8. Docker 重建后验证四种 Pipeline 的 Match、确认、停止、续跑和完成流程。

## 验收标准

- 打开首页立即看到任务列表和待审核任务，不再先看到大幅装饰内容。
- 用户可在 30–60 秒内完成一条任务的填写和 Match 提交。
- 不进入详情页也能判断任务状态、当前阶段、失败原因和可执行动作。
- Match ERROR 可在两次操作内筛选出来，确认前能清楚看到 OK/ERROR 数量。
- 日志文件增大后只读取新增内容，暂停刷新或向上滚动时不会被强制拉到底部。
- Stop、Resume、Confirm Match 都有明确确认、加载和结果反馈。
- 四条 Pipeline 的专用字段和阶段名称由注册表正确生成。
- 桌面端信息密度适合长期监控，移动端仍能完成创建、审核和停止操作。
- 不触碰现有 pipeline 的计算、断点、输出和并发定义。
