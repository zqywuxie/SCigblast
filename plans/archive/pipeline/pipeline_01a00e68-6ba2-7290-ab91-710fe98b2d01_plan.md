# IR stage-first 输出、Datapoint 身份与处理性能优化计划

## 目标与版本边界

本计划覆盖三个目标：

1. 将 IR 多数据集输出从 `output/<dataset>/<stage>` 调整为 `output/<stage>/<dataset>`。
2. preprocess 只指定统一的 IgBLAST 阶段目录；Datapoint 取消 `sample__dupNN`，增加 `batch,sample` 字段。
3. 优化 preprocessing、expression、diversity、CSR、SHM 的处理性能、并发、内存和断点续跑，同时保持现有计算定义和结果口径不变。

优化边界：

- 只修复崩溃、空输入、异常输入、内存占用、并发竞态、流式处理和断点恢复问题。
- 不修改 UMI、clone、D50、SHM、CSR、expression 等指标的统计定义。
- 不新增 `corrected_v2`，不改变合法输入的既有数值；所有优化必须通过逐列回归测试。

所有 marker/checkpoint 写入：

```text
PIPELINE_LAYOUT_VERSION=stage-first-v1
PIPELINE_SCHEMA_VERSION
CALCULATION_CONTRACT=frozen-current
```

## 1. IR 多数据集改为 stage-first

### 1.1 目标结构

当前结构：

```text
output/<dataset>/01.match
output/<dataset>/02.fastp
...
output/<dataset>/07.igblastn_out
```

改为：

```text
output/
├── 01.match/<dataset>/...
├── 02.fastp/<dataset>/data|report/...
├── 03.IR_split_output/<dataset>/...
├── 04.clean_data/<dataset>/...
├── 05.pandaseq/<dataset>/...
├── 06.representative/<dataset>/...
└── 07.igblastn_out/<dataset>/...
```

merged variant 对应：

```text
06.igblastn_out/<dataset>/...
```

各 dataset 仍作为独立的 01–07 任务运行。阶段脚本不能直接一次扫描全部 dataset，因为 clean、PANDAseq、representative 和 IgBLAST 内仍存在按 sample 名登记或生成临时 batch 的逻辑，合跑会产生同名覆盖风险。

### 1.2 dataset 标签与共享 submission

dataset 标签默认取规范化输入目录 basename：

```text
/colddata/.../230714 → 230714
/colddata/.../230901 → 230901
```

basename 重复时追加稳定 path hash。

`SCIGBLAST_SUBMISSIONS` 保持为独立共享集合，每个输入目录加载全部 submission，仍由 Note 字段选择正确批次，不能恢复按数组下标配对。

顶层原子写入：

```text
output/dataset_manifest.csv
```

字段：

```text
dataset,input_root,input_mode,submission_sources,barcode_csv
match_dir,fastp_dir,split_dir,clean_dir,pandaseq_dir
representative_dir,igblast_dir,status,error
```

### 1.3 runner 路径契约

外层 runner 不再把 child 的 `SCIGBLAST_OUTPUT_ROOT` 改成 `output/<dataset>`，而是传递：

```text
SCIGBLAST_OUTPUT_ROOT=<shared output root>
SCIGBLAST_DATASET_LABEL=<dataset>
```

child 集中构造：

```text
MAPPING_SUMMARY=01.match/<dataset>/sample_barcode_summary.csv
FASTP_DIR=02.fastp/<dataset>/data
FASTP_REPORT_DIR=02.fastp/<dataset>/report
SPLIT_OUTPUT_DIR=03.IR_split_output/<dataset>
CLEAN_DIR=04.clean_data/<dataset>
PANDASEQ_DIR=05.pandaseq/<dataset>
REPRESENTATIVE_DIR=06.representative/<dataset>
IGBLAST_OUTPUT_DIR=07.igblastn_out/<dataset>
```

逐阶段传入明确输入/输出路径，并审计各脚本内部基于共享 `OUTPUT_ROOT/<stage>` 的默认值。任何 summary、临时文件或 `.DONE` 都不得落到未包含 dataset 的共享路径。

### 1.4 日志、marker 和清理

```text
output/logs/<dataset>/pipeline.log
output/.pipeline_state/<dataset>/.pipeline_stage_01.match.DONE
...
output/.pipeline_state/<dataset>/.pipeline_stage_07.igblast.DONE
```

marker 记录：

```text
layout_version,dataset,raw_input_path
stage_input_path,stage_output_path
mapping_hash,config_hash,script_hash
completed_count,failed_count,status,timestamp
```

只有全部 dataset 完成才写：

```text
output/.pipeline_state/.pipeline.DONE
```

清理只作用于 `<stage>/<dataset>`。fastp marker、split checkpoint、representative state 和 IgBLAST `.batches` 都必须位于当前 dataset 子目录。

旧 dataset-first marker 和旧 IgBLAST batch manifest 不自动复用。通过 `layout_version=stage-first-v1` 使其失效；如需迁移旧结果，单独生成迁移 manifest，不能只根据目录存在判定完成。

IgBLAST 内表示计算分批的 summary 字段 `batch` 改名为 `batch_index`，避免和 Datapoint 的来源 batch 混淆。

## 2. preprocess 只指定一个目录

正常配置仅保留：

```text
INPUT_DIR=output/07.igblastn_out
```

preprocess 读取 `dataset_manifest.csv`，只扫描登记且 IgBLAST 状态可用的：

```text
07.igblastn_out/<dataset>/
```

每条输入保存：

```text
dataset         = dataset manifest 中的标签
relative_sample = 相对于 dataset IgBLAST 根的完整路径
sample          = relative_sample 最后一层
batch           = sample 目录的直接上一层
sample_key      = (dataset, relative_sample)
```

`batch` 继续遵守用户指定的“样本目录上一层”规则；dataset 单独保留在 manifest。如果样本直接位于 dataset 根下，batch 为空字符串，不能误取 output 或 input root 的父目录。

内部计算仍使用完整 `sample_key`，不能使用 `(batch,sample)` 分组。Datapoint 输出：

```text
batch,sample,...metrics
```

删除 `_display_sample_labels()`，不再出现 `__dupNN`。如果 `(batch,sample)` 仍重复，Datapoint 保留多行，manifest 标记碰撞并保存真实来源。

manifest 字段：

```text
dataset,input_root,relative_sample,batch,sample
internal_sample_key,public_id_collision,collision_count,collision_group_id
available_receptors,tcr_path,bcr_path,status,error
```

junction 输出：

```text
junction_peps/<dataset>/<relative-sample>/<TCR|BCR>/<locus>.csv
```

source/sample checkpoint 同时绑定 dataset、relative sample、源文件 fingerprint、layout/schema version 和 `CALCULATION_CONTRACT=frozen-current`。

## 3. 建立不可变计算基线

新增 `10X_split/pipeline/tests/`，从当前代码和真实小样本生成冻结基线：

- 每个 source 的输入行、过滤后行、输出行和行顺序；
- UMI、expression、diversity、D50、CSR、SHM 的全部输出字段和值；
- Datapoint、junction 文件和 manifest 的字段、类型、空值表示及排序；
- 当前单进程结果，作为所有并发实现的唯一结果基准。

验收采用稳定排序后的逐列比较：整数、字符串、布尔值和空值表示必须完全一致；浮点计算必须保持原计算顺序，输出值必须一致。任何需要更换公式、分母、过滤条件、聚合顺序或数值库的优化均不实施。

## 4. 只做处理层和调度层修复

保留现有模型函数及其调用顺序。允许的修改包括：

- 消除重复读取、重复扫描、重复 concat 和无用中间副本；
- 预先校验文件、必需列和数据类型，异常样本写入状态与错误日志；
- 修复临时文件重名、共享 DONE marker、PID 误判和并发覆盖；
- 对样本任务设置 worker 上限、内存门槛、失败隔离和进度输出；worker 数同时受配置、CPU、当前可用内存和样本估算峰值约束；
- 每个 dataset/stage 维护独立 PID registry 和进程组；`stop.sh` 只读取本 pipeline registry，先 TERM、限时等待后再处理残留子进程，不再全量扫描服务器进程；
- 单个样本失败时同阶段其他样本继续，阶段结束汇总失败并返回非零，后续阶段不启动；
- 保持单个样本内部现有过滤、分组、聚合和模型执行顺序。

空输入、坏行、缺列和零分母只在进入计算前被识别并记录。不得为这些情况新造指标值，也不得把错误行转成零值后继续参与计算。

## 5. 流式输入准备与 source checkpoint

当前整表读取会放大内存。流式改造只负责输入准备，不重新定义模型聚合：

```text
source TSV → 按原规则分块读取/过滤 → 保序中间文件 → 原有模型函数
```

每个 source 输出：

```text
.postprocess/preprocessed/<source_id>.tsv
.postprocess/preprocessed/<source_id>.DONE.json
```

`source_id` 使用 canonical source path hash。marker 记录：

```text
source_path,size,mtime_ns,header_fingerprint
filter_parameters,calculation_contract
input_rows,filtered_rows,output_rows,umi_sum,output_size
```

约束：

- 分块路径必须与当前内存路径产生相同记录、相同字段、相同行顺序和相同空值表示。
- 不使用新的 SQLite 唯一键、去重或重新聚合替代当前计算逻辑。
- 临时文件校验后原子替换；未完成文件不能被 checkpoint 接受。
- source 预处理并发按磁盘吞吐设置，默认 1–2；不得同时在同一大文件内部改变记录处理顺序。
- 可用内存低于配置门槛时停止领取新任务并写日志；正在运行的任务正常收尾，避免强杀造成半成品。
- 如果分块实现无法通过冻结基线，继续使用当前内存实现，不以近似结果换取性能。

## 6. 样本级并发与 checkpoint

并发边界固定在独立 `sample_key=(dataset,relative_sample)` 之间。每个 worker 对一个样本调用现有 preprocessing 和 models，不新增 `calculate_*_files()`，不重写 expression、diversity、CSR 或 SHM 公式。

SHM 仅允许调度优化：

- 新增可配置 worker 上限，并计算 pipeline 总进程预算，避免样本级进程与 SHM 子进程相乘。
- worker 接收原函数所需数据，结果按原始索引恢复，再交给现有汇总逻辑。
- 不启用零突变快速路径，不修改 `one_alignment_only`，不替换 pairwise2，不改变 alignment 参数。
- 如使用缓存，只能缓存“完全相同输入调用原函数得到的完整结果”，缓存命中与未命中必须逐字段一致。

每个内部 sample 保存：

```text
.checkpoints/<internal_key_hash>/base_metrics.csv
.checkpoints/<internal_key_hash>/full_metrics.csv
.checkpoints/<internal_key_hash>/manifest.json
.checkpoints/<internal_key_hash>/junction.DONE
.checkpoints/<internal_key_hash>/sample.DONE.json
```

checkpoint 绑定 source fingerprint、脚本 hash、配置 hash 和 `CALCULATION_CONTRACT=frozen-current`。单个 source 改变只失效对应 sample；最终 Datapoint 按原 discovery order 从样本级结果重建。

## 7. 计算定义冻结清单

以下内容禁止修改：

- 输入记录的保留/排除条件和过滤先后顺序；
- UMI/`umi_counts` 的来源、权重、去重及聚合口径；
- sample、chain、locus、CDR3、isotype 等计算分组键；
- expression 的分母、字段含义和百分比口径；
- diversity 的 clone 分组、丰度及 D50、Shannon、Pielou、Gini、Simpson 公式；
- SHM 的坐标解释、alignment 参数、突变判定、加权方式和汇总公式；
- CSR 的 isotype、pair、分母和输出口径；
- 数值类型、舍入、NaN/空字符串/零值表示以及结果列顺序。

代码评审中只要改动触及上述任一项，即从本轮优化中剔除。性能改造只能改变任务如何调度、数据如何安全搬运和中间结果如何恢复。

## 8. 验证矩阵

### IR stage-first

- 230714、230901、231222 同时运行，各阶段均生成 `<stage>/<dataset>`。
- 每阶段只读取同 dataset 上游目录。
- submission 目录保持共享，由 Note 选择正确批次。
- 单 dataset 失败不阻塞其他 dataset，但顶层 DONE 不写入。
- 修改一个 dataset 的 mapping/config，只失效该 dataset 及下游。
- cleanup 不删除其他 dataset。

### preprocess 身份

- 只传统一 `07.igblastn_out` 根即可发现全部登记 dataset。
- 实际 163 个内部样本和 17 组同名 sample 不合并、不加后缀。
- Datapoint 每行具有直接父目录 batch。
- 两个同名 07 根、跨 dataset 同 sample、同 dataset 不同 pair 同 sample 均保持独立。
- `(batch,sample)` 冲突在 manifest 中可追溯。

### 模型

- 当前串行代码先生成冻结输出，优化后逐文件、逐行、逐列比较。
- preprocessing 的保留集合、顺序、UMI 字段和值完全一致。
- expression、diversity、CSR、SHM 的列集合、类型、空值和数值完全一致。
- 单 worker 与多 worker 结果在恢复原顺序后完全一致。
- 空表、缺列、坏行和 worker 异常只验证能准确报错并隔离样本，不为其定义新的指标结果。

### 性能和恢复

- 使用 1M 与真实 20M 行 BCR benchmark。
- SHM 测试 8/16/32/64 workers，记录 rows/s、wall time、peak RSS、临时盘和原函数调用次数。
- 流式输入准备的峰值内存受 chunk 限制；原模型仍整表处理时，其单样本峰值不得高于当前实现，并通过样本并发窗口限制 pipeline 总内存。
- 在各 checkpoint 发布前强制中断，确认重启不重复且不接受半成品。

## 9. 推荐实施顺序

```text
1.1 IR stage-first路径 + dataset manifest + marker迁移
→ 1.2 preprocess单输入根 + batch字段 + 取消后缀
→ 1.3 冻结当前串行输出并建立逐列回归
→ 1.4 样本级并发 + 进程预算 + sample checkpoint
→ 1.5 等价流式输入准备 + source checkpoint
→ 1.6 全量回归测试与并发性能基准
```
