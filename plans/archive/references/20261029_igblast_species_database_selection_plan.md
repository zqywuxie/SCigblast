# 统一 IgBLAST 流程与物种数据库选择

## 目标与兼容性

新建任务使用统一的 IgBLAST 流程，先选择物种，再选择该物种可用的数据库；只有一个可用数据库时自动选中并显示。统一流程支持直接扫描目录并指定样本与链，也支持 Submission 输入；所有物种使用同一输出布局和续跑规则。保留历史 `pig_igblast` 任务的原类型、执行器、输出路径和续跑逻辑，不迁移已有结果。历史 Base 任务按保存的原有配置恢复；若没有保存物种，保持原运行逻辑，避免擅自假定历史配置。

## 实施

1. 在统一参考配置中定义物种及数据库 ID、数据库目录、aux、internal_data 和链支持情况。初始覆盖 human、pig、cat、dog，以部署环境中实际安装的资源为准；猪现有参考的目录为 `pig_chain`、aux 为 `pig.aux`，其他参考按各自实际配置映射。数据库选项来自受控清单，不接受任意路径；仅提供经过验证的组合，未安装的资源应清楚提示。保留数据库 ID 和版本，防止默认库变更影响既有任务。
2. 修改 `web/pipeline_registry.json`、`web/templates/index.html`、`web/static/index.js` 和 `web/static/directory-input.js`：新建页面合并为一个入口，提供级联物种、数据库选择；任务详情和复制任务展示并保留选择，变更选择时使已有扫描和预检结果失效。历史猪任务仍可识别和管理。
3. 在 `web/app.py` 的请求模型及任务创建、目录扫描、Match、审核、重试和续跑中校验并持久化物种与数据库 ID，传入任务环境。修改 `pipeline_input_manifest.py` 与 `Igblast_base/pipeline/01.match_sample.py`：目录 manifest 绑定选择；Submission 的物种经明确规范化后与任务选择一致，冲突则拒绝运行；运行前再次验证 manifest，避免输出标签和实际数据库不一致。
4. 将参考解析复用到 `web/preflight.py`、`pipeline_igblast_cache.py`、`Igblast_base/pipeline/run_igblast_base.sh` 和 `Igblast_base/pipeline/05.work_igblastn.sh`，使预检、执行参数及缓存指纹使用同一数据库 ID、路径和物种。确保任务值在配置文件加载后仍生效，正确设置 IgBLAST organism 和 aux；逐链检查 V/J、按实际参数检查 D、可选 C、internal_data 与占位参考。资源不可用时阻止分析并指出具体原因。
5. 统一新任务的阶段输出布局：以 `output/<阶段>/<数据集>/<样本>/<配对>/` 为公共路径，fastp 的 `data/` 与 `report/` 保留各自分区，Match 和各阶段汇总保留在阶段根目录，IgBLAST 按链输出 TSV。各阶段使用同一套安全路径构造和碰撞检测，支持一个样本的多对 FASTQ，统一 FASTQ 文件命名以保证上下游衔接。核对两种流程的 FASTQ 处理、配对和过滤差异；更新使用说明、部署挂载与打包清单。
6. 统一 fastp、clean、PANDAseq、IgBLAST 的续跑契约：阶段和样本/链两级完成标记均记录版本、输入、处理参数和依赖指纹；检查产物完整性后复用，变化时只重跑受影响的工作，并使下游相关结果失效。历史任务保留原布局和原 runner 的读取、续跑能力，不直接将新标记套用到旧产物。

## 验证

- 使用可控参考目录验证物种和数据库组合的白名单、默认选择、资源缺失、占位库、无效输入及配置覆盖顺序；检查缓存因物种或数据库变化而失效。
- 对每个实际可用物种分别覆盖目录和 Submission 模式，验证扫描、审核、物种冲突拒绝、逐链预检、运行参数及输出标注一致；切换选择后不能复用旧扫描或预检。
- 验证每阶段统一输出路径、同一样本多配对、同名输入及安全名称碰撞；验证中断后样本/链级续跑，以及输入、参数、数据库或产物变化后的缓存失效与下游重算。
- 使用实际猪样本比较原 Pig 与统一流程的 AIRR 结果及过滤计数，记录预处理和输出布局差异；在具备参考库与工具的环境中对其余物种执行端到端测试。未安装库或缺乏真实样本时记录验收限制。
- 验证历史 Pig 和历史 Base 的查看、重试、续跑和复制；确认现有并发限制、容器打包和数据库挂载不变。
